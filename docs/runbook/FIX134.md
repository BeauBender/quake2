# FIX134: the renderers' PVS decompressor stops at the visibility lump

`Mod_DecompressVis` (`src/client/refresh/files/pvs.c`), the PVS decoder of gl1, gl3 and soft, read
its run-length row with no end bound: a zero run whose count byte was the lump's last byte, or runs
that ended before the row was full, read past the visibility lump, and a zero run that carried past
the row wrote past the static row buffer. FIX118's `Mod_CheckVis` bounds each cluster's start offset
only. The decoder now takes the bytes of the lump left after the cluster's offset (each renderer keeps
the lump's length as `vislen` beside `vis`) and decodes as ref_metal's `rm_decompress_vis`
(`src/client/refresh/metal/rm_pure.c`) does: a row whose input ends inside it is all visible, as
without visibility, and a zero run stops at the row's end. A cluster of -1 and a map without vis still
return each renderer's `mod_novis`.

The cluster index is the map's too: a leaf's cluster is a signed short the loaders stored unchecked,
and gl1, gl3 and soft guarded only -1 in `ClusterPVS`, so a cluster at or past `numclusters`, or below
-1, read `bitofs[cluster]` past the offset table `Mod_CheckVis` checked. All three now call the shared
`Mod_ClusterPVSRow` (`pvs.c`), which returns the no-vis row for any cluster outside
`[0, numclusters)`, as ref_metal's `Mod_ClusterPVS` does, and all four loaders run a fifth shared check,
`Mod_CheckLeafs` (`src/client/refresh/files/models.c`), which refuses a map with visibility whose leaf
has such a cluster, as ref_metal's `rm_leaf_ok` does. `R_MarkLeaves` (gl1, gl3, soft) indexes the row
by each leaf's cluster (`vis[cluster >> 3]`) after a -1 test; with the load check every other cluster
is below `numclusters`, inside the row, and without visibility `R_MarkLeaves` returns before the loop.
`tests/check-bsp-loader.sh` requires the fifth check in every loader.

`CM_DecompressVis` (`src/common/collision.c`) has no such hole: FIX23 bounded it to the lump's end
and to the row, and `test_bspgraph.c` covers it. It is unchanged.

The unit cases are in `tests/unit/test_pvs.c` (`pvs_*`). Each row is decoded from a heap copy of
exactly the lump's length (a read past it is a heap overflow the address sanitizer reports) and from
a buffer whose bytes after the lump are a canary (a read past it changes the row without the
sanitizer). `pvs_zero_run_stops_at_row_no_asan` sees the write bound without a sanitizer: a full row
of `0x01` is decoded first, then a four-byte row whose zero run would carry 255 bytes, and the static
buffer's bytes after the four must keep their `0x01`. `pvs_empty_input` (no byte of the lump left)
and `pvs_row_past_buffer` (a row longer than `MAX_MAP_LEAFS / 8`) cover the two edges, and
`pvs_cluster_out_of_range` the cluster guard. The leaf cases are `bspcheck_leaf_*` in
`tests/unit/test_bspgraph.c`.
