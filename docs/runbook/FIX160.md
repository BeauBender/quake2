# FIX160: map entity text reaches the command buffer through ExitLevel's gamemap

Property: text a game module hands to `AddCommandString` runs as at most one command line.

## Cause

`ED_NewString` turns the two characters `\n` in an entity value into a newline. `ExitLevel` builds `gamemap "<level.changemap>"` and hands it to `gi.AddCommandString`, which was `Cbuf_AddText`. `Cbuf_Execute` splits lines at a newline even inside quotes, and at a `;` outside quotes, so a `target_changelevel` map value with a newline, or with `";cmd;"`, started a second command.

## Design

One layer, in the engine, with no API or savegame change and no game function added. `SV_GameAddCommandString` in `src/server/sv_game.c` (the import's signature is unchanged) applies `Cbuf_Execute`'s own split rule (`src/common/cmdparser.c`): it counts `"` and refuses the whole text, with a console message, if it holds a `\n` before its last character or a `;` while the quote count is even. A `;` inside quotes is an argument and stays allowed. This protects every game module, the addons (xatrix, rogue, ctf) included.

- `\r` is not refused: `Cbuf_Execute` does not split at it, so CRLF text runs as it did on main.
- `src/game/g_main.c` is unchanged from main. The round-1 guard in `ExitLevel` is dropped: the engine rule catches every shape it did, and it had no test in the unit suite.

## Callers of `gi.AddCommandString` in `src/game`

- `ExitLevel` (`g_main.c`): `gamemap "<name>"\n`, one trailing newline, unchanged for any real level name.
- `player/client.c`: `menu_loadgame\n`, one trailing newline, unchanged.

## Test

`sv_game_command_text_never_adds_a_command` in `tests/unit/test_server.c`: the plain quoted line runs once; a `;` inside quotes runs once; CRLF runs once; an embedded newline, a quote closed by map data followed by `;`, and a bare `;` are each refused, with the console message asserted and the probe command not run. Red on the round-1 head (the probe ran), green with the rule.
