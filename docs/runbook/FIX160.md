# FIX160: map entity text reaches the command buffer through ExitLevel's gamemap

Property: a level name from map or entity data can only name a level. It never adds a command.

## Cause

`ED_NewString` turns the two characters `\n` in an entity value into a newline. `ExitLevel` builds `gamemap "<level.changemap>"` and hands it to `gi.AddCommandString`, which was `Cbuf_AddText`. `Cbuf_Execute` splits lines at a newline even inside quotes, so a `target_changelevel` map value with a newline started a second command.

## Design

Both layers, no API or savegame change, no game function added:

- Engine, `SV_GameAddCommandString` in `src/server/sv_game.c` (the import's signature is unchanged): text may hold a line break (`\n` or `\r`) only as its last character, otherwise it is refused whole with a console message. This also protects addon game modules (xatrix, rogue, ctf).
- Game, `ExitLevel` in `src/game/g_main.c`: a level name holding `"`, `;` or a line break is refused. The engine cannot reject `"` or `;` for every caller, since an addon may legitimately send quoted arguments; the stock game's only user of them is this one.

## Callers of `gi.AddCommandString` in `src/game`

- `ExitLevel` (`g_main.c`): `gamemap "<name>"\n`, one trailing newline, unchanged for any real level name.
- `player/client.c`: `menu_loadgame\n`, one trailing newline, unchanged.

## Test

`sv_game_command_text_never_adds_a_command` in `tests/unit/test_server.c`: the plain line still runs once; `"base2\nt_probe\n"` and a `\r` variant run nothing. Red on main (the probe ran), green with the fix.
