# FIX200: CI uses no Homebrew

`.github/workflows/macos.yml` ran `brew update` and `brew install make` on every build, and built
with Homebrew's `gmake`. Both came in with upstream's first workflow and were never approved for
this fork. The step also failed a build once, when `brew update` got a 403 from GitHub.

## What changed

- The "Install build dependencies" step is gone, and the build and unit-test steps call `make`,
  Xcode's (GNU Make 3.81), which the Makefile already builds with. `make -n -j3` and
  `make -n -j3 test` plan the same targets as before. No other step or job changed.
- `tests/check-removed-deps.sh` refuses `brew` and `gmake` in any case, with no word bounds, in
  `.github` (workflows and local actions) and `scripts/ci-*.sh`. This covers a `run:` line, a
  `run: |` block, `/opt/homebrew/bin/brew`, `/usr/local/bin/brew` and a Homebrew action. It fails if
  `.github/workflows` is missing or grep itself errors.
- The check's mutants add one Homebrew line (`brew install`, `brew update`, both brew paths,
  `gmake`) to a copy of a workflow and to a copy of a local action; each must be refused.
- `scripts/setup.sh` hints "install gh from cli.github.com".

## Result

The check was red on the old `macos.yml` (four lines) and is green after the change. The real
build runs in CI on the pull request.
