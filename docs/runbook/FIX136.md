# FIX136: a committed check that forces every CI-required skip

[FIX115](FIX115.md) gave every skip of `tests/check-*.sh` a `<NAME>_REQUIRE` guard and
`tests/check-ci-parity.sh`, which checks the shape of each guard. That a guard really fails under its
variable was shown once, by the forced-skip runs recorded in FIX115's runbook, and nothing re-ran them.
`tests/check-require-guards.sh` now runs them, in the gate (the `tests/check-*.sh` glob of
`scripts/test.sh`) and in CI (`tests/ci-checks.txt`).

## What it does

- **The variables** are read at run time from the two files that set them: the `NAME_REQUIRE` keys of
  `.github/workflows/macos.yml` and the `NAME_REQUIRE=` assignments of `scripts/test.sh`, outside
  comments. Today: the six of `invariants_macos` (`CHECK_IOS_REQUIRE`, `CHECK_EVIDENCE_REQUIRE`,
  `CHECK_AUTORELEASE_POOL_REQUIRE`, `CHECK_STATIC_MODULES_REQUIRE`, `CHECK_BENCH_REQUIRE`,
  `CHECK_CVAR_DOCS_SELFTEST_REQUIRE`) and the gate's two (`CHECK_REF_METAL_REQUIRE`,
  `CHECK_METAL_SHIM_REQUIRE`). Every `_REQUIRE` of the caller is unset first, so the gate's own
  `CHECK_REF_METAL_REQUIRE=1` reaches no case.
- **Each case** forces its check's skip with a stub ahead of `PATH` or a stripped `PATH`, runs the real
  check with the variable set and wants a non-zero exit and a line that names the variable, then runs it
  with the variable unset and wants exit 0. Each run is bounded by perl's `alarm`
  (`REQUIRE_GUARDS_WALL`, 600 s by default).
- **The accounting.** The check fails when a variable that CI or the gate sets has no case, when a case
  names a variable that neither sets, and when the lines of a check that read a set variable (an
  expansion, outside comments) are more or fewer than the cases and the unforced list account for. So a
  new variable, or a new guard of a set variable, needs a case.
- **The unforced list** names the guards that cannot be forced cheaply, each with its reason. An entry
  whose check no longer reads its variable fails.
- **The mutants** run on scratch trees: every top-level entry linked, `tests/` a directory of links
  with the one check under test a changed copy. The real files are never changed. Each mutant must let
  the forced skip pass with the variable set, which is what the case refuses.

## The cases

| Variable | Check | Forced by | Variable set | Variable unset |
| --- | --- | --- | --- | --- |
| `CHECK_IOS_REQUIRE` | `check-ios.sh` | `uname` = Linux | fails | passes |
| `CHECK_IOS_REQUIRE` | `check-ios.sh` | an `xcrun` refusing `iphonesimulator` | fails | passes |
| `CHECK_EVIDENCE_REQUIRE` | `check-evidence.sh` | a `PATH` of `/usr/bin` and `/bin` without python3 | fails | passes |
| `CHECK_AUTORELEASE_POOL_REQUIRE` | `check-autorelease-pool.sh` | `uname` = Linux | fails | passes |
| `CHECK_STATIC_MODULES_REQUIRE` | `check-static-modules.sh` | `uname` = Linux | fails | passes |
| `CHECK_BENCH_REQUIRE` | `check-bench.sh t_freq t_probe_first` | `uname` = Linux | fails | passes |
| `CHECK_BENCH_REQUIRE` | `check-bench.sh t_snap_argv` | a `PATH` without bash | fails | passes |
| `CHECK_CVAR_DOCS_SELFTEST_REQUIRE` | `check-cvar-docs-selftest.sh` | a `git` whose plain `cat-file` fails | fails | passes |
| `CHECK_REF_METAL_REQUIRE` | `check-ref-metal.sh` | `uname` = Linux | fails | passes |
| `CHECK_METAL_SHIM_REQUIRE` | `check-metal-shim.sh` | an `xcrun` refusing `metal` | fails | passes |

The `git` stub refuses only a call whose first argument is `cat-file`, as
`check-cvar-docs-selftest.sh` asks for the upstream commit. `check-cvar-docs.sh --selftest` calls
`git -c ... cat-file` in its own fixture repositories, so a stub that refuses every `cat-file` fails
that self-test with the variable unset, too.

The last three are not set by CI or the gate. Their guards were traced in FIX115's round 2 and round 3
reviews.

## The mutants

- **print-only**, one per case: the case's guards turned back into a guard that only prints, round 1 of
  FIX115 (`[ ... != 1 ] || echo ...` and then the skip).
- **bench-round1**: `check-bench.sh`'s `t_freq` guard as `|| bad "..."` with the skip's `return 0` after
  it. `bad` only counts; a sub-test fails by its status.
- **inverted**: `check-evidence.sh`'s guard as `= 1 ] || { ...; exit 1; }`, which fails only when the
  variable is unset.
- **next-line-if**: `check-autorelease-pool.sh`'s guard removed and the skip's message followed by a
  one-line `if [ "${CHECK_AUTORELEASE_POOL_REQUIRE:-0}" = yes ]; then exit 1; fi`.
- **piped-while**: `check-metal-shim.sh`'s `|| bad ...` inside `echo x | while read -r _l; do ...; done`,
  so `fail=1` is lost with the loop's subshell.

The last three are the forms the FIX115 round 3 review accepted as out of the shape lint's reach.

## Runs

On an Apple M6, in a `heavy.sh` hold: 8 variables, 10 cases, 4 unforced guards, 14 mutants refused.
The first run took 62 s; its one failure was the cvar-docs case, with a `git` stub that refused every
`cat-file` (see above). The final run took 70 s, every case failing with its variable set and passing
with it unset, and every mutant refused.
