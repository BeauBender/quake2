# FIX136: a committed check that forces every CI-required skip

[FIX115](FIX115.md) gave every skip of `tests/check-*.sh` a `<NAME>_REQUIRE` guard and
`tests/check-ci-parity.sh`, which checks the shape of each guard. That a guard really fails under its
variable was shown once, by the forced-skip runs recorded in FIX115's runbook, and nothing re-ran them.
`tests/check-require-guards.sh` now runs them, in the gate (the `tests/check-*.sh` glob of
`scripts/test.sh`) and in CI (`tests/ci-checks.txt`).

## What it does

- **The variables** are read at run time from the two files that set them: every `env` map (workflow,
  job and step) of `.github/workflows/macos.yml` and every `NAME_REQUIRE=` prefix of a step's `run`,
  read by ruby's yaml as `tests/check-ci-parity.sh` reads the file (no ruby is a failure), and the
  assignments of `scripts/test.sh` outside comments (`NAME_REQUIRE=...`, also after `export`, and
  `: "${NAME_REQUIRE:=...}"`; any other `_REQUIRE` token there fails). Today: the six of `invariants_macos` (`CHECK_IOS_REQUIRE`, `CHECK_EVIDENCE_REQUIRE`,
  `CHECK_AUTORELEASE_POOL_REQUIRE`, `CHECK_STATIC_MODULES_REQUIRE`, `CHECK_BENCH_REQUIRE`,
  `CHECK_CVAR_DOCS_SELFTEST_REQUIRE`) and the gate's two (`CHECK_REF_METAL_REQUIRE`,
  `CHECK_METAL_SHIM_REQUIRE`). Every `_REQUIRE` of the caller is unset first, so the gate's own
  `CHECK_REF_METAL_REQUIRE=1` reaches no case.
- **Each case** forces its check's skip with a stub ahead of `PATH` or a stripped `PATH`, runs the real
  check with the variable set and wants a non-zero exit and the guard's own message (`<test>: NAME=1 and`
  for a case that names a test, `NAME=1 and` otherwise), then runs it with the variable unset and wants
  exit 0. One run proves one guard: a case that claims another count or names two tests fails. Each run is bounded by perl's `alarm`
  (`REQUIRE_GUARDS_WALL`, 600 s by default).
- **The accounting.** The check fails when a variable that CI or the gate sets has no case, when a case
  names a variable that neither sets, and when the lines of a check that read a set variable (an
  expansion, `$NAME` or `${NAME...}`, outside comments) are more or fewer than the cases and the unforced list account for. So a
  new variable, or a new guard of a set variable, needs a case.
- **The unforced list** names the guards that cannot be forced cheaply, each with its reason. An entry
  whose check no longer reads its variable fails.
- **The mutants** run on scratch trees: every top-level entry linked, `tests/` a directory of links
  with the one check under test a changed copy. The real files are never changed. In each tree the
  unmutated copy runs first as a control, which the case must accept; then the case must refuse the
  mutant.

## The mutants

- **print-only**, one per case: the case's guards turned back into a guard that only prints, round 1 of
  FIX115 (`[ ... != 1 ] || echo ...` and then the skip).
- **bench-round1**: `check-bench.sh`'s `t_freq` guard as `|| bad "..."` with the skip's `return 0` after
  it. `bad` only counts; a sub-test fails by its status.
- **inverted**: `check-evidence.sh`'s guard as `= 1 ] || { ...; exit 1; }`, which fails only when the
  variable is unset.
- **next-line-if**: `check-autorelease-pool.sh`'s guard removed and the skip's message followed by a
  one-line `if [ "${CHECK_AUTORELEASE_POOL_REQUIRE:-0}" = yes ]; then exit 1; fi`.
- **piped-while**: `check-metal-shim.sh`'s `|| bad ...` inside `echo x | while read -r _l; do ...; done`,
  so `fail=1` is lost with the loop's subshell.

The last three are the forms the FIX115 round 3 review accepted as out of the shape lint's reach.

## Runs

On an Apple M6, in a `heavy.sh` hold: 8 variables, 10 cases, 4 unforced guards, 14 mutants refused.
The first run took 62 s; its one failure was the cvar-docs case, with a `git` stub that refused every
`cat-file` (see above). The final run took about 70-100 s, host-dependent, every case failing with its variable set and passing
with it unset, and every mutant refused.

## Round 2

The three review passes of round 1 found the same three Importants.

- **One run proves one guard.** `t_freq` and `t_probe_first` ran as one case, and either guard firing
  satisfied it, so a broken `t_probe_first` guard went unnoticed. They are two cases now, the table
  refuses a case that claims another count than 1 or names two tests, and the forced run must show the
  guard's own message, not only the variable's name. The **probe-first** mutant turns only
  `t_probe_first`'s guard print-only: its case refuses it, and the same mutant run with `t_freq` too
  still fails on `t_freq`'s guard, the old case's blind spot.
- **The variables read by a parser.** The old regex missed a quoted YAML key and a `NAME_REQUIRE=1`
  prefix inside a `run:`, and in `scripts/test.sh` the `:=` and `export` forms. The accounting mutants
  (on copies of the two files) are **wf-dquote** (`"CHECK_FOO_REQUIRE": 1`), **wf-squote**
  (`'CHECK_FOO_REQUIRE': 1`), **wf-run-prefix** (`CHECK_FOO_REQUIRE=1 scripts/ci-checks.sh`),
  **sh-assign-default** (`: "${CHECK_FOO_REQUIRE:=1}"`) and **sh-export** (`export CHECK_FOO_REQUIRE=1`),
  each refused for lacking a case, and **sh-unclassified** (`echo CHECK_FOO_REQUIRE`), refused as a token
  the reader cannot classify.
- **Every expansion counted.** A check's reads now count `$NAME` and `${NAME-...}` as well as `${NAME}`
  and `${NAME:...}`, as `tests/check-ci-parity.sh` treats guard expansions. The **dollar** mutant adds a
  `[ "$CHECK_EVIDENCE_REQUIRE" != 1 ] || exit 1` guard to a copy of `check-evidence.sh`, which is
  refused: the check reads the variable on 2 lines and the cases prove 1.
- **Notes.** Each mutant tree runs its unmutated copy first, which the case must accept, so a tree that
  fails early cannot pass for a refusal. The alarm still kills the check, not a process group: every run
  takes the check's skip path, which no check reaches after starting a long-lived child, the logs are
  files, so a child left behind cannot hold the check, and a process group of its own would take the
  check out of the terminal's, so Ctrl-C would no longer reach it.
