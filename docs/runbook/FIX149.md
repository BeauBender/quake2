# FIX149: check-image-decoder when leaks(1) cannot attach

## What happened

On a build host with Developer Mode off (`DevToolsSecurity -status`: "Developer mode is currently
disabled") and a locked screen, leaks(1) cannot inspect a process: the developer-tools authorization
it waits for is never answered. `leaks --atExit -- /usr/bin/true` under a 60 s alarm is killed by
the alarm (status 142). `tests/check-image-decoder.sh` then:

- printed the test's own "20 loops of 81 cases, 12863 checks, 0 failed", waited out its whole bound
  (`IMGDEC_CHECK_SECONDS`, default 300 s) and failed with "leaks(1) outlived its 300 s bound";
- left the `imgdecode_plain` that leaks(1) ran behind, stopped (state `T`), orphaned. A stopped
  process cannot end itself at `--bound`, so it stays until someone kills it.

leaks(1) starts its target as its own child and holds it stopped (`TN` under a hanging leaks(1));
killing leaks(1) reparents the target to launchd, still stopped.

## The fix

- **A probe.** Before the leak run, the check runs `leaks --atExit --` on a program that only
  exits (`leakprobe`, built from the check's own `probe.c`), with a bound of
  `IMGDEC_LEAKS_PROBE_SECONDS` (default 20, validated like `IMGDEC_CHECK_SECONDS`: a whole number
  of seconds, not 0). If the probe outlives it, the check fails at once with one line:
  "leaks(1) could not inspect a process within 20 s: it needs Developer Mode (DevToolsSecurity
  -enable) or an unlocked session that answers the developer-tools authorization". It fails; it
  does not skip: the leak run is required wherever leaks(1) exists. Only a probe that outlives its
  bound fails there; any other leaks(1) failure shows in the leak run, with its output.
- **No stopped leftovers (`reap`).** When a bound passes, the watchdog calls `reap <run> <name>`
  instead of a plain `kill`. `reap` signals the run only while its parent is the check's shell
  (`$$`): the shell is blocked in `wait` for it and has not reaped it, so its PID is the run's and
  not a reused one. It stops the run first (a stopped process reaps no child, and a child that has
  exited stays its zombie, so no child PID can be reused while `reap` works), kills with SIGKILL
  each child whose program basename is `<name>` (`leakprobe` for the probe, `imgdecode_plain` for
  the leak run, `-` for the runs without leaks(1)), then kills the run. There is no PID file and no
  name-only match: a process is a target only if it is the stopped run's own child and runs the
  named program.
- **A self-test**, `tests/check-image-decoder-selftest.sh` (in `tests/ci-checks.txt`), runs the
  whole check with stub leaks(1) first on PATH, in scratch: (a) a stub that hangs; (b) a stub that
  spawns its target suspended (`POSIX_SPAWN_START_SUSPENDED`, as leaks(1) does), sends it SIGSTOP
  and hangs; (c) a stub that passes the probe and does (b) to the leak run's target, with an
  unrelated `imgdecode_plain` started by the self-test beside it; (d) a stub that behaves; (e) an
  invalid probe bound (`abc`, `0`); (f) `reap` itself, extracted from the check.

## Disposition probe (case f)

`reap` called on a PID that is not the caller's child (an orphan running `imgdecode_plain`, as a
PID the caller reaped and the system reused would be), then on a run that is the caller's child
with two children, `imgdecode_plain` and `other`:

```
orphan: alive
run: killed
named child: killed
other child: alive
```

Case (c) shows the same end to end: the unrelated `imgdecode_plain` started by the self-test is
still alive after the check reaped the leak run's stopped `imgdecode_plain`.

## Red and green

The self-test against the check before the fix (38 s):

```
check-image-decoder: leaks(1) outlived its 8 s bound and was killed
check-image-decoder-selftest: (a) a hanging leaks(1): the check did not fail at its probe with the cause (status 1)
check-image-decoder: leaks(1) outlived its 8 s bound and was killed
check-image-decoder-selftest: (b) a leaks(1) that stops its target: the check did not fail at its probe (status 1)
check-image-decoder-selftest: (c) the leak run's stopped target is still there (or was never started)
check-image-decoder-selftest: (e) IMGDEC_LEAKS_PROBE_SECONDS='abc' was not refused (status 0)
check-image-decoder-selftest: (e) IMGDEC_LEAKS_PROBE_SECONDS='0' was not refused (status 0)
check-image-decoder-selftest: (f) tests/check-image-decoder.sh defines no reap function
check-image-decoder-selftest: 6 case(s) failed
```

The red run also left a stopped `imgdecode_plain` behind (the self-test's case (b) against the old
check); it was killed by hand, by its PID, after checking its program.

After the fix (23 s):

```
check-image-decoder-selftest: ok (6 cases: a hang, a stopped probe target, a stopped leak-run target, a good leaks(1), a bad probe bound, reap)
```

The real check on the host, with the real leaks(1), `IMGDEC_CHECK_SECONDS=60 tests/check-image-decoder.sh`:
status 1 after 22 s, last line

```
check-image-decoder: leaks(1) could not inspect a process within 20 s: it needs Developer Mode (DevToolsSecurity -enable) or an unlocked session that answers the developer-tools authorization
```

The list of stopped processes (`ps -x -o pid,stat,comm | awk '$2 ~ /^T/'`) was the same before and
after: one `imgdecode_plain` from an earlier probe, not started by this run; no new `leakprobe`,
`imgdecode_plain` or leaks(1) remained.

## On a host where this fires

Enable Developer Mode (`DevToolsSecurity -enable`, an administrator's password), or run the gate in
an unlocked session and answer the developer-tools authorization once.
