# FIX138: the image decoder's type restriction on an older SDK

FIX115's first CI run (run 44549989930, image `macos-26-arm64`) failed `tests/check-tvos.sh` and
`tests/check-visionos.sh`: every `imgdecode.o` "does not need `_kCGImageSourceAllowableTypes`".
`imgdecode.c` sets that key only when an SDK version macro (`__MAC_OS_X_VERSION_MAX_ALLOWED`,
`__TV_OS_VERSION_MAX_ALLOWED`, `__VISION_OS_VERSION_MAX_ALLOWED`, ...) is 27.0 or later, because the
key is declared from the 27.0 SDKs on (`IMAGEIO_AVAILABLE_STARTING(27.0, ...)` in `CGImageSource.h`).
The runner's Xcode has the 26.x SDKs, so the decoder there is built without it. The build host has
the 27.2 SDK.

The fix keeps building with the older SDK (the runner's is the one CI uses) and relies on the
restriction already behind the key: `IMGDEC_DecodeImageIO` compares `CGImageSourceGetType` with the
extension's type (`IMGDEC_TypeCheck`) before it reads the size or decodes a pixel, and refuses a
PNG, JPEG or TGA named as another of the three with `IMGDEC_ERR_MISMATCH`. The code path is
unchanged; what changed is that it is tested and pinned on both kinds of SDK:

- `IMGDEC_TEST_NO_ALLOWABLE_TYPES` builds the decoder as an older SDK does. `tests/check-image-decoder.sh`
  builds the host test a second time with it, requires the binary not to import
  `_kCGImageSourceAllowableTypes`, and runs it: "png named .tga", "tga named .png" and the other
  cross-type cases must come back `IMGDEC_ERR_MISMATCH`. A mutant decoder with the type check removed
  fails those cases.
- `tests/check-tvos.sh` and `tests/check-visionos.sh` ask the SDK whether it declares the key (a
  one-line probe compiled against it; any compile error but "undeclared identifier" fails the check).
  Every `imgdecode.o` must import `_CGImageSourceGetType`, and `_kCGImageSourceAllowableTypes` too
  where the SDK declares it. On an older SDK they print a note naming the SDK version.
- The `invariants_macos` job prints `xcodebuild -version` and the SDK version in a Toolchain step.

`tests/check-tvos.sh` and `tests/check-visionos.sh` are back in `tests/ci-checks.txt`.

`tests/check-image-decoder.sh` stays in `tests/ci-local-only.txt` for a cause apart from the SDK: its
one failing check on the runner is "encode 1x1 kind 1: not the same bytes back", an encode round trip
of a single pixel with alpha 0 (19 37 34 0). It is the only image of the test whose every pixel has
alpha 0; the larger alpha 0 or 255 images pass there. It passes on the build host with and without
the key, so the SDK is not its cause: the runner's macOS 26 ImageIO does not give that pixel back byte
for byte. The check's message now prints the first pixel that differs, so the next run on that system
shows whether the encoder or the decoder changed it. A follow-up card returns the check to CI.

## Running it

```sh
tests/check-image-decoder.sh
CHECK_TVOS_REQUIRE=1 tests/check-tvos.sh
CHECK_VISIONOS_REQUIRE=1 tests/check-visionos.sh
tests/check-ci-parity.sh
```
