# FIX108: closing a card by any route leaves it with a terminal state label

## The bug

The loop's dependency check counts a card as done only when its issue is closed and labelled
`state:done`. Only the ship path set that label. A card closed another way (`gh issue close` from another
session, or the web UI) kept `state:backlog`, so every card that depends on it read as blocked. TASK28
(#38) was closed by hand on 2026-11-15 and blocked TASK56, TASK60, and INFORM11 and TASK59 behind them,
for two days. A sweep on 2026-11-17 found 24 closed cards with a stale `state:backlog`, all relabelled
by hand.

## The fix

`.github/workflows/card-close-labels.yml` runs on `issues: types: [closed]` and nothing else. It sets
the labels from the issue's own labels and its close reason (`state_reason`):

| close | labels before | edits |
| --- | --- | --- |
| `completed`, not `state:promoted` | any of `state:backlog`, `state:staged`, `state:in-progress`, `state:review` | add `state:done`, then remove each of those it has |
| `completed`, already `state:done` | as above | remove those it has, add nothing |
| `not_planned`, `duplicate`, no reason, or `state:promoted` | as above | remove those it has, add nothing |
| any | no `state:*` label (not a card) | nothing |

Reopening is left to the loop: the workflow does not run on it. A run from an earlier close can start after
the issue was reopened (it was queued, or waited behind another close in the concurrency group), so the
run reads the issue's state first, after the number guard, and edits nothing unless the issue is closed
now. The close reason still comes from the event: two closes in a row, completed and then not planned,
queue two runs, and the first adds `state:done`, which the second does not take off.

Only a close by the owner counts: the job has `if: github.actor == github.repository_owner`. GitHub lets
an issue's author close their own issue as completed, and a close by an outside author must not mark a
card the owner labelled done. Such a close leaves the labels as they are, as before this card.

A close made with another workflow's `GITHUB_TOKEN` starts no workflow (Actions starts none for events
from that token), so it is not covered either. No workflow in this repository closes issues today; one
that does must set the labels itself or use another token.

A `state:*` label added to the repository later must be added to `decide` and to the label list of the
check's lint; until then a card closed with only that label keeps it.

The `state:done` label goes on first, then each removal is its own `gh issue edit`. So a card reads as done
as soon as the first call lands, and a run that fails part-way leaves it done, not unlabelled. Each call is
idempotent: adding a label the issue has is a no-op, and a removal that fails is an error only if a fresh
read of the labels still shows that label (someone may have removed it meanwhile). A second run on the
same issue therefore makes no edit.

The decision is the `decide` function of the run block, between the `card-close-labels: decide begin`
and `end` marker lines. It is written into the run block, not kept in `.github/scripts/`, because a
script there needs a checkout: `actions/checkout` is an action, and reading the file through the API needs
`contents: read`. Either breaks "issues: write and nothing else, no action".

## Safety

- `permissions: {}` at the top, `issues: write` on the one job, nothing else.
- The job runs only for a close by the repository owner.
- No `uses:`: only the preinstalled `gh`, with `GH_TOKEN: ${{ github.token }}` and
  `GH_REPO: ${{ github.repository }}`.
- From the event, only `github.event.issue.number` and `github.event.issue.state_reason`, both through
  `env:`. No `${{ }}` expression appears inside the run block, not even in a comment (Actions expands
  those too). The number is refused unless it is all digits.
- No `gh` call in the edit loop reads its stdin (each has `</dev/null`), so none can eat the decisions
  file the loop reads.
- The labels are read with `gh api --paginate repos/$GH_REPO/issues/$N/labels --jq '.[].name'` into a
  file, and `decide` only compares that file with `grep -Fx` against its five fixed names. It prints only
  those fixed names, so no title, body, author or label name ever reaches a shell string or a command
  argument.
- `ubuntu-latest` (a free standard runner), `timeout-minutes: 5`, and a concurrency group per issue
  number that queues instead of cancelling.

## The check

`tests/check-card-close-labels.sh` (in the gate's `tests/check-*.sh` glob) needs no network and no `gh`.
It reads the workflow with awk. The lint is an allow-list over the whole file, so a spelling it does not
know is refused rather than passed. It asserts, each under a tag:

| tag | rule |
| --- | --- |
| `trigger` | `on: issues: types: [closed]` and nothing else |
| `top-perms` | a top-level `permissions: {}` and no other |
| `job-perms` | `issues: write` exactly on every job, no permissions key elsewhere |
| `uses` | no `uses` key in any spelling: quoted, in a flow mapping, on any line but a comment |
| `expr` | every `${{ }}` in the file, comments and the run block included, is exactly one of `github.workflow`, `github.event.issue.number`, `github.event.issue.state_reason`, `github.token`, `github.repository`, and stands on an `env:` value line or the concurrency `group:` line (so no `github[...]`, no `toJSON`, no function, no odd spacing) |
| `run` | exactly one run block, whose value is exactly `\|` or `\|-`: no plain, quoted or folded scalar, no anchor |
| `shell` | exactly one `shell:`, and it is `sh` |
| `flow` | outside the run block, no flow collection but `permissions: {}` and `types: [closed]` |
| `anchor` | outside the run block, no anchor, alias or tag (`&`, `*`, `!`) |
| `key` | outside the run block, every line a comment or a plain unquoted key and its value |
| `container` | no `container:` and no `services:` |
| `if`, `owner` | no `if:` but the job's, which is exactly `if: github.actor == github.repository_owner` |
| `state-read` | the run block reads the issue's state |
| `timeout`, `runner`, `concurrency`, `labels` | a `timeout-minutes`, `ubuntu-latest`, a concurrency group keyed by the issue number, the five state labels named |

Each assertion has mutants, scratch copies of the workflow edited with sed or awk, that the check must
refuse under that assertion's tag; a mutant that changes nothing fails the check.

Then it cuts the whole run block out of the workflow, checks it with `/bin/sh -n`, and runs it with
`/bin/sh -e` (Actions runs `shell: sh` as `sh -e {0}`) with a stub `gh` first on `PATH`. The stub logs its
arguments, serves the labels and the issue state, and fails an add or a removal on request. Eight cases:
the number `7;id` (exit 1, no `gh` call at all); completed with `state:backlog` (`issue edit 7 --add-label
state:done`, then `--remove-label state:backlog`); completed with all four non-terminal labels; not
planned; the issue reads `open` (exit 0, no edit); a failed removal whose label is still there (exit 1)
and one whose label is gone (exit 0); a failed add (exit 1). In every case no `gh` call may read its
stdin. Run-block mutants delete the number guard, the state check, the removal re-read, its test, the
stdin redirect and a `fi`; each must fail a case (tag `run-block`). The job's `if:` is a runner-only
condition, so the lint asserts its exact text instead.

Last, it cuts `decide` out of the workflow and runs it with `/bin/sh -e` on 14 label sets: completed with backlog, with review,
with promoted and backlog, with all four non-terminal labels; not_planned with backlog; duplicate; an
empty reason; no state label (completed and not_planned); no labels; already done; done and backlog;
look-alike names (`state:backlog-old`, ` state:in-progress`); and names holding shell syntax, which must
not run.

  `- {name: x, uses: actions/checkout@v4}`, a quoted `"uses":` key, `${{ github['event']['issue']['title'] }}`

## Live proof

An `issues` workflow runs only from the default branch, so the live proof comes after merge: open a
throwaway issue labelled `state:backlog` and close it as completed. It must end with `state:done` and no
other state label. Open a second one, close it as not planned, and it must end with no state label. Then
delete both, or record the two runs' logs here.
