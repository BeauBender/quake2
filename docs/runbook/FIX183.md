# FIX183: the never-less-than-main scrub counter reads HOME the way tscrub does

## What happened

`tests/check-gate-parallel.sh` holds `tscrub` to leave no home path that `tscrub_main` (a copy of the old
scrubber) replaced, by counting occurrences with `_scount`. `_scount` took the home through `awk -v`, which
decodes backslashes, and did not drop trailing slashes, while both scrubbers read `HOME` from `ENVIRON` and
trim the slashes. For a backslash or trailing-slash `HOME` the count was 0 on both sides, so the comparison
could not see a `tscrub` that left the home unscrubbed.

## What changed

- `_scount` reads `HOME` from `ENVIRON` (set to its argument for that awk) and drops trailing slashes, as the
  scrubbers do. `_scrow` makes the count comparison first, so it is the one that reports.
- Two direct `_scount` rows: a trailing-slash home (`/u/qq/` counts 2 in `/u/qq/a /u/qq`) and a backslash home
  (counts 1 where `awk -v` gave 0).
- `tscrub` runs its awk under `LC_ALL=C`, so it stays safe if reused outside this script. A row runs it under
  `LC_ALL=en_US.UTF-8` on a line with a non-ASCII byte after the home. The awk on this host (version 20200816)
  does not abort on it, so the row guards the pin and is not red here without it; an awk that aborts on an
  invalid sequence would make it red.

## Mutants

Each is run by `ttyself` from a copy of the self-test and must be caught by `scrub`.

| Mutant | Change | Caught by |
|---|---|---|
| `tty-count-awk-v` | `_scount` reads the home with `awk -v` again | the backslash row |
| `tty-count-no-trim` | `_scount` keeps trailing slashes | the trailing-slash row |
| `tty-home-unscrubbed` | `tscrub` never scrubs | the count comparison on every row |
