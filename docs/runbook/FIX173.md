# FIX173: the `game` cvar never holds a value FS_GameDirValid refuses

Cause: FIX169 validated the game directory in a server's `svc_serverdata`, and
`FS_BuildGameSpecificSearchPath` refuses a bad directory, but the `game` cvar itself took any
string. A server's `svc_stufftext` runs `game ../x` or `set game ../x`; the raw value stayed in the
cvar and in `userGivenGame` (restored at disconnect), and `ogg.c` formats the cvar into
`"%s/music/"` and opens tracks below it, past `FS_FOpenFile`.

The rule: a write of `game` that `FS_GameDirValid` refuses keeps the old value, prints one line
(`game: refused "<40 bytes>", not a single directory name.`) and reaches neither `userGivenGame` nor
the search paths. `""` and a name such as `ctf` pass as before. `FS_GameDirValid` also refuses a name
of `MAX_QPATH` bytes or more now (the size of `userGivenGame` and `cl.gamedir`, where a longer name
was truncated); one validator, so FIX169's `svc_serverdata` check gets it too.

## Where the check sits

`Cvar_RefusedGameValue` in `src/common/cvar.c`, next to FIX153's `Cvar_RefusedFromServer` (which
refuses by source; this refuses by value, for every source). Every write of a value goes through one of:

- `Cvar_SetVar`: `Cvar_Set`, `Cvar_ForceSet` (both via `Cvar_Set2`), the console's `game x`
  (`Cvar_Command`), `set game x` (`Cvar_Set_f` calls `Cvar_Set`), `+set`, `config.cfg` (`set` lines),
  a server's `svc_stufftext` (it runs the same commands), and the latched branch. A latched write is
  checked before the latch (`latched_string`) is stored, so `Cvar_GetLatchedVars` only applies a value
  that was checked when written.
- `Cvar_FullSet`: `set game x s`, `FS_BuildGameSpecificSearchPath`'s reset to `""`.
- `Cvar_Get` / `Cvar_GetNew`: creation and the default of an existing cvar (`+set game ../x` before
  registration, a server line that creates the cvar first); a refused value becomes `""`.

`Cvar_Command` copies into `userGivenGame` only when `FS_GameDirValid` accepts the argument, so the
disconnect restore never sees a refused value. `frame.c`'s initial copy reads the cvar, already checked.

## Read paths that format `game`, `fs_gamedir` or `userGivenGame` into a path

| Path | Covered |
| --- | --- |
| `ogg.c` `"%s/music/"` (`gameCvar->string`) | yes, the cvar cannot hold a bad value |
| `FS_BuildGameSpecificSearchPath` (`fs_gamedir`, pak and raw dirs) | yes; it kept its own check as a second line |
| `FS_Gamedir()` users: `sv_save.c` saves, `sv_cmd.c` demos, `scrnshot`, `FS_ExecAutoexec`, config write | yes, `fs_gamedir` is built from the checked name; its other input is the `-portable`/home setup, not the network |
| `cl_network.c` `Cvar_Set("game", userGivenGame)` at disconnect | yes, the source is checked, and the write is checked again |
| `cl_parse.c` `svc_serverdata` | yes, FIX169's check, same validator |
| `cl_entities.c` and `g_svcmds.c` read `game` for a comparison, not a path | not a path |
| `FS_FOpenFile` | FIX170 |

## Tests

`tests/unit/test_cvar_gamedir.c`: `../x`, `.`, `..`, `a/b`, `a\b`, `a:b`, a control byte, `0x7f`, a
newline and a 64-byte name each leave `game`, `userGivenGame` and the latch unchanged through
`Cvar_Set`, `Cvar_ForceSet`, `Cvar_FullSet`, a console `set game` and `game` line as player's and as
server's text, a latched write (server state set) and the latched apply. `""`, `ctf` and a valid latched
`xatrix` are accepted. No protocol, savegame or module API change; `game` keeps its flags.
