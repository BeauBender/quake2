# FIX154: `condump` and `record` validate their file name

`condump <name>` wrote `<gamedir>/<name>.txt` and `record <name>` wrote `<gamedir>/demos/<name>.dm2`
with the argument unchecked. `FS_CreatePath` refuses a path containing `..`, but `Q_fopen` does not,
so a name containing `..` could open a file outside the game directory when the target directory
already existed.

## What changed

- `FS_SafeRelativeName` (`src/common/filesystem.c`, declared in `common.h`) is the one check: not
  empty, no `..`, no leading `/` or `.`, no `:`, no backslash. It is the same rule as
  `CL_DownloadFilter`'s path test, plus the backslash; it lives in the filesystem file because that
  is linked into the unit suite.
- `Con_Dump_f` (`src/client/cl_console.c`) and `CL_Record_f` (`src/client/cl_main.c`) call it before
  building the path, print one console line and write nothing. No new cvar or command.
- Test: `fs_safe_relative_name` in `tests/unit/test_filesystem.c`. It was red before the helper existed
  (the suite did not build), and its control half shows the unchecked construction escaping a
  temporary game directory through `Q_fopen`.
