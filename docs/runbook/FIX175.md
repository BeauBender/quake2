# FIX175: check-ref-metal.sh's summary is built from per-block segments

## What happened

The last line of `tests/check-ref-metal.sh`, `check-ref-metal: ok (...)`, was one `echo` that named every
sub-check's result. Each new sub-check (TASK179's effect table, TASK199's tone-map order) had to edit
that one long line, in the middle of it, so parallel lanes added to it conflicted on every merge.

## The change

Each sub-check block now ends with one line of its own, `seg <n> "<joiner><text>"`, and the final `echo`
prints the sorted segments and names no sub-check. `seg` appends `<n><TAB><text>` to a file in the
check's scratch directory; the final line is `sort -n | cut -f2- | tr -d '\n'` over it, still under
`[ "$fail" = 0 ]`.

The number is the segment's place in the printed line, not the block's place in the file. The blocks run
in the file's order (host tests, cvar table, vocabulary, flush points, ...), while the printed line has
a different order, and the effect table's pieces are interleaved with the gate's. Keeping the printed
text identical meant keeping that order, so a plain append in run order was not enough. The joiner
(`; ` or `, `) is part of the text.

To add a sub-check: end its block with `seg <n> "; <text>"`, with an `n` no other segment uses (the
header note in the script says the same). A new segment at the end of the line takes the next number.

## Proof

The summary line of the unchanged script and of the changed one, run in the same hold, are byte
identical, and both exit 0.
