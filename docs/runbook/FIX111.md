# FIX111: the gate-nap-uncut mutant is caught on every run

`tests/check-bench.sh` mutates the gate's nap cut (`core/snap.sh`, `then _gt_nap=$_gt_left; fi`
to `then :; fi`) and requires `t_gate_poll` to fail. On 2026-11-17 a merge gate under a load
average of 12 to 14 failed with `mutant gate-nap-uncut passed t_gate_poll`, and FIX106's rework
saw the same line once on the M6; the same head had passed an hour before.

## The cause

`t_gate_poll` drove the gate with `gate_wait=1`. The gate takes whole seconds (`date +%s`): when
its first snapshot crossed a second boundary, `now - t0` was already 1, the gate broke
(`gate`) before its first nap, and the uncut 20 s nap never ran. How likely that was depended on
where in a second the test began and on how slow the snapshot was, so load made it worse.

## The fix

`t_gate_poll` now runs the gate with `gate_wait=4`, a stub reader that stays busy (50 %), and
`BENCH_GATE_POLL=20`. With 4 s of wait no boundary can skip the first nap (it would need the
first snapshot to take 4 s). The cut run takes about 4 s; the uncut one naps 20 s. The test
times it with `perl -MTime::HiRes`, and asserts that the elapsed time stays under `gate_wait`
plus 3 s (the readings' share), besides the existing 12 s wall bound that reaps a nap that
was not cut. No whole-second difference decides the outcome.

The same edge in `settle-nap-uncut`: `bench_settle` reads `date +%s` for `t0`, then again for the
time left, so a boundary between the two reads made `left` 0 and ended the wait before any nap
with `gate_settle=1`. `t_settle`'s cut-nap case now uses `gate_settle=4` (bound 10 s against 20 s uncut).

## Proof under load

Four `yes > /dev/null` busy loops (started and killed by pid inside the same heavy.sh hold, load
average 6.9 to 13.7), 20 runs each of `sh tests/check-bench.sh t_gate_poll`:

- the unmutated tree: passed 20 of 20;
- a tree with `gate-nap-uncut` applied: caught (the test failed) 20 of 20.

## The other time-bounded checks

Looked over for the whole-second edge: `gate-no-bound` (`t_gate`, gate_wait=2: lower bound only,
`_t >= 2` is safe for floored seconds, and it needs no nap cut), `gate-no-hold`, `settle-no-bound`
(`gate_settle=2`, lower bound `>= 2` only, safe), `settle-no-poll`, `settle-zero-polls`,
`settle-nap-uncut` (fixed as above), the lock's poll and grace tests (`bare-no-grace`,
`t_lock_guard`; the lock FIX106 added: `t_lock_fifo` and its queue tests) which decide on state
files and process liveness, not on second differences, and the `while date -le tl+3` waits,
which wait at least 3 real seconds. None of them share the edge.
