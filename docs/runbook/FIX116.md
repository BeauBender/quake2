# FIX116: the unit suite under ASan and UBSan in the gate and CI

Review finding AR-03 (`docs/reviews/2026-11-17-fork-window.md`): nothing in the gate or CI built or ran the unit
suite with `ASAN=1` or `UBSAN=1`, so an out-of-bounds read in a hostile-input case was reported only when it changed
a pin or an assertion. `tests/check-unit-sanitizers.sh` closes that.

## What it runs

In a scratch copy (`mktemp -d`) of `Makefile`, `third_party/sdl3.make`, `src/`, `tests/unit/` and `tests/pins/unit/`
(`third_party/SDL3` is linked, not copied; the suite does not build it), with `MAKEFLAGS`, `CFLAGS`, `LDFLAGS`, `CC`
and the caller's sanitizer options unset:

```sh
ASAN_OPTIONS=halt_on_error=1:abort_on_error=1:detect_leaks=0 \
UBSAN_OPTIONS=halt_on_error=1:abort_on_error=1:print_stacktrace=1 \
make -C <scratch tree> -j<ncpu> ASAN=1 UBSAN=1 UPDATE_PINS= TEST_ARGS= test
```

The Makefile's own sanitizer handling is reused: `ASAN=1` and `UBSAN=1` imply `DEBUG` (`-O0 -g`), add
`-fsanitize=address` and `-fsanitize=undefined` to the compile and the link, and give every test object
`-fno-sanitize-recover=undefined`. The objects go to the scratch tree's `build/debug/test`, so `build/`, `release/`
and `debug/` of the checkout, the objects of `make test` and a `config.mk` of the checkout are not touched or read.

## The options and why

- `-fno-sanitize-recover=undefined` (from the Makefile): the first UBSan report ends the run.
- `halt_on_error=1`, `abort_on_error=1` for both runtimes, set in the check: the first report stops the run, and it
  ends by `SIGABRT`, a non-zero status whatever the caller's `exitcode` or options say.
- `detect_leaks=0`: LeakSanitizer is not supported by the ASan runtime on macOS on Apple silicon. An explicit
  `detect_leaks=1` is refused (`AddressSanitizer: detect_leaks is not supported on this platform.`, status 134,
  macOS 27.2 arm64), so the value is written out only so another platform runs the same check. Nothing else is
  relaxed.
- The check reads the binary's symbols and fails unless it references `__asan_init` and an aborting UBSan handler
  (`__ubsan_handle_*_abort`), so a Makefile that dropped either flag is seen.
- A run that exits 0 with a sanitizer report in its output (`runtime error:`, `ERROR: AddressSanitizer`,
  `SUMMARY: ...Sanitizer`) fails too. The first report and the end of the run are printed.

## Where it runs

`scripts/test.sh` runs every `tests/check-*.sh` through `scripts/gate-checks.sh`, so the gate runs it with the other
checks, in parallel. It is listed in `tests/ci-checks.txt`, so the `invariants_macos` job runs it through
`scripts/ci-checks.sh`; no workflow edit was needed. It has no skip: a missing `make`, `cc` or `nm` fails it.

## Time

On the build host (macOS 27.2.1, arm64, 12 CPUs, load about 5), held under the host lock: 5 s wall for the whole
check, 4 s of it the build and run of the 433 cases. Well under the 3 minutes the card set, so it is not added to
`gate_first` in `scripts/test.sh`.

## The mutant, red first

The bound FIX19 added to `PCX_Decode` (`src/client/refresh/files/pcx.c`) that a packed row (1, 2 or 4 bits a pixel)
of the given width fits in `bytes_per_line` (`IMGSIZE_PCXRowFits`) was deleted in the worktree, then restored with
`git checkout --`:

- plain `make test`: red, from assertions, not from a pin: `FAIL imgsize_pcx_packed_row
  (tests/unit/test_imgsize.c:282): check failed: pic == NULL` (and lines 290, 298), `yq2test: 433 tests, 1 failed`.
  That case asserts the refusal, so this bound is caught without a sanitizer too.
- `tests/check-unit-sanitizers.sh`: red at the first out-of-bounds read, before the assertion:
  `SUMMARY: AddressSanitizer: heap-buffer-overflow pcx.c:433 in PCX_Decode` (the 4-bit path reading the line buffer
  past its `bytes_per_line` bytes, from `imgsize_pcx_packed_row`), `make: *** [test] Abort trap: 6`, status 1.
- Restored: `yq2test: 433 tests, 0 failed`, `check-unit-sanitizers: ok`.

## Run it alone

```sh
tests/check-unit-sanitizers.sh
```

The last line is `check-unit-sanitizers: ok: ...` or `check-unit-sanitizers: FAILED: ...`. To run the same build in
the checkout instead (it writes `build/debug/test`): `make ASAN=1 UBSAN=1 test`.
