# FIX197: a same-name reload builds the bounce records again, and each bounce mutant names the check that refuses it

Two follow-ups from the review of TASK189 slice 2 ([TASK189](TASK189.md), "Notes from review (slice 2)").

## 1. The stale lightmap id

### Cause (traced, not reproduced)

`RM_RTDir_Lights` (`src/client/refresh/metal/rm_rtdirscene.c`) uploads the map's lights, its emissive faces and,
through `RM_RTDir_Bounce`, the bounce records with the world's lightmap array (`rmb_rtdir_set_bounce`, which keeps
the id as `brec_lmtex` in `rmb_rtdir.m`). It returned early when the world pointer and the model name both matched
the last upload. With `flushmap 1`, or when the same map name loads again, `rm_model.c` frees the world and its
`lmtex` and makes a new world. If the new world takes the old one's address, the early return skipped the upload,
and `brec_lmtex` kept the freed id. Texture ids are handed out lowest free slot first (`rmb_take_id` in
`rmb_resource.m`), and the old world's slot is freed before the new world's array takes one. So the new array often
gets the old id back, and then the kept id names the live new array, which is harmless. The bounce went dark only
when the new array got a different id, which the old key missed and the new key catches. Nothing was read out of
bounds.

### Fix

The key is a pure function, `rm_rtdir_lights_current` (`rm_rtdir.c`, declared in `header/rm_rtdir.h`). The upload
is current only for the same world, the same name and the same lightmap array (`rm_world_t.lmtex`). The glue
stores the array it uploaded (`dir_lmtex`, reset by `RM_RTDir_Init`). It has no branch of its own: its one early
return is the function's verdict.

| Case | Verdict | Today |
|---|---|---|
| Same world, same name, same array | kept (early return) | kept |
| Same world, same name, new array (the reload) | built again | kept: the bug |
| A new world | built again | built again |
| A new name | built again | built again |
| No array before or now (both 0) | kept | kept |
| An array gone to 0, or made where there was none | built again | kept |
| The pass reopened (`dir_world` set to NULL) or nothing uploaded yet | built again | built again |
| A NULL name | built again | not reachable (`model_t.name` is an array) |

The array-gone-to-0 row differs from today. Today's early return kept the freed id there. Building again hands the
back end 0, and the bounce reads no array. A new array that took the old id back names a live array, the
current world's. So keeping the records there is correct: the map, and with it its records, is the same.

The exposure fit keeps its own key (`fit_world`, `fit_map`). It reads the map's luxels, not the array. A
same-name reload gives the same fit, so it is left as it was.

A same-name map with different contents, at the same address and with the same id, would still keep the old
records. The GPU bounds keep those reads in range. A per-load serial on `rm_world_t` would close that; it touches
`model.h`, which is outside this card.

### Tests

- `tests/metal/rm_rtdir_test.c`, `test_reload`: every row above. Committed first with the function on today's key
  (`8d75b396`). Then three rows failed: `reload: a same-name reload with a new lightmap array is not built again`,
  `an array gone to none` and `an array made where none was`.
- `test_reload_glue`: `RM_RTDir_Lights`'s one early return is `rm_rtdir_lights_current(..., wm->world->lmtex)`,
  followed by the stores, `dir_lmtex` named four times. Its mutant `reload-glue-lmtex` passes the stored array for

  `reload: a same-name reload with a new lightmap array is not built again`. Any other failure is reported as
  "for another reason". Segment 7.6 reports `1 reload mutant`.

## 2. The mutant names

`rm_rtdir_bounce` and `rm_rtdir_tri_lm` are pinned whole. Before this card, every body mutant was refused by that
pin, whatever its name said. `bounce_broken` now checks each rule on its own, ahead of the whole-body pins. Each
mutant must be refused by its own check's line (`strcmp`, not just a refusal). A mutant refused by another check
fails the test, and the test prints both lines.

| Mutant | File | The check that refuses it (its line) |
|---|---|---|
| `bounce-shadow-ray` | `rm_rtdir.metal` | the shadow ray: the bounce casts a ray of its own at its hit |
| `bounce-unstyled` | `rm_rtdir.metal` | the styled lightmap: the hit's light is not the frame's lightmap array |
| `bounce-view1` | `rm_rtdir.metal` | the view gate: the bounce is not traced by the view's own show and scale |
| `bounce-own-lm` | `rm_rtdir.metal` | the own lightmap: the bounce reads a lightmap at the pixel, not at its hit |
| `bounce-exposed` | `rm_rtdir.metal` | the exposure: the bounce's term is exposed with the traced light |
| `bounce-no-albedo` | `rm_rtdir.metal` | the albedo: the bounce's term is not its record's albedo times the light and the scale |
| `bounce-unbounded` | `rm_rtdir.metal` | the layer bound: the faces the bounce passes are not bounded by MTL_RTDIR_LAYERS |
| `bounce-sky-numbers` | `rm_rtdir.metal` | the bounce's numbers: its direction is not the tile's third and fourth numbers |
| `bounce-sky-lit` | `rm_rtdir.metal` | the sky's colour: the bounce adds the sky at a hit, which the sky light already counts |
| `bounce-unbounded-rec` | `rm_rtdir.metal` | the record bound: a bounce record past the table is read |
| `bounce-dropped` | `rm_rtdir.metal` | the bounce does not join the exposed light once, in the world's write |
| `bounce-unbounded-slice` (new) | `rm_rtdir.metal` | the slice bound: a lightmap slice past the array's layers is read |
| `tri-lm-diffuse-st` (new) | `rm_rtdir.metal` | the lightmap coordinates: rm_rtdir_tri_lm does not read the hit triangle's lightmap coordinates |
| `tri-lm-unbounded-vert` (new) | `rm_rtdir.metal` | the vertex bound: rm_rtdir_tri_lm reads a triangle or a vertex past the buffers |
| `view1-bounce` | `mtl_rtsky_math.h` | mtl_rtsky_bounces does not trace the bounce under the picture and view 7 alone |
| `bounce-sky-shade` | `mtl_rtsky_math.h` | mtl_rtsky_bounce_at does not shade world faces alone and pass water and glass |
| `bounce-not-alone` | `mtl_rtsky_math.h` | mtl_rtsky_alone is not the views 5, 6 and 7 |
| `bounce-layers` | `mtl_rtsky_math.h` | the layer bound: mtl_rtsky_bounce_at passes faces past MTL_RTDIR_LAYERS (a new check of its own) |
| `bounce-two-rays` | `mtl_rtsky_math.h` | the bounce is not one ray a pixel in the bound, or its view not 7 |
| `bounce-white-array` | `rmb_rtdir.m` | the bounce's lightmap array: index 7 is not the world's lightmap array |
| `bounce-other-texture` | `rmb_rtdir.m` | the bounce's lightmap array: index 7 is not the world's lightmap array |
| `bounce-no-lmtex` | `rm_rtdirscene.c` | the bounce is not given the world's lightmap array |

Before this card, `bounce-white-array` was refused by the binding list (`the direct pass binds a texture beyond its
known eight`), and `bounce-other-texture` by the dynamic lights' check. `binding_broken` now checks the bounce's
array first: its binding at index 7, `brec_lmtex`'s one store, and the records' count. These pins moved from the
dynamic lights' check, and none was dropped. `bounce-own-lm` and `bounce-exposed` had fallen through to
`kernel_broken` or the kernel join. They are now refused by `bounce_broken` alone, with no fallback.

The host test reports `22 bounce mutants refused` (19 before: the three new ones). Each count is a mutant refused
by its own line.

- `make ref_metal`, `make`
- `tests/check-ref-metal.sh` and `tests/check-ios.sh`
- `tests/check-runbook-index.sh` and `tests/check-doc-links.sh`
- the pins: every stock, Enhanced, Retro and RT2 scenario, and every RT-primary record, each against main

All of it ran on `91967db4`, against main at `d93444d3`.

- `make ref_metal` and `make`: exit 0.
- `tests/check-ref-metal.sh`: ok. The direct-light segment: "1019 checks, 0 failed, 8 fit mutants, 1 reload mutant,
  18 sky mutants and 22 bounce mutants refused".
- `tests/check-ios.sh`: ok (54 mutants refused).
- `tests/check-runbook-index.sh` and `tests/check-doc-links.sh`: ok.
- **Pins**, seeded:
  - 37 of 37 scenarios outside `rtprimary-*` are byte-identical to main (`rt-*` 15 of 15, `retro*` 2 of 2);
  - 20 of 20 RT-primary records on a fresh load are byte-identical to main (TASK126's list, without
    `rtprimary-models-temporal`).
- **The engine reload.** It ran at 640x480 with `+set r_presentation 3 +set r_rt_temporal 0 +set r_rt_stats 1` on
  the command line, with `map base1`, then `set flushmap 1` and `map base1` again. Both sides ran ray traced and
  drew about 300 frames after each load.
  - **Main:** 2 exposure-fit lines and 2 bounce lines. The new world took a new address, so both keys changed and
    both rebuilt.
  - **The branch:** 1 exposure-fit line and 1 bounce line. The new world took the old address (the fit's own key,
    the pointer and the name, did not change), and the bounce kept its records: the lightmap array came back with
    the same id.
  - So neither run met the case the fix is for: the same address with a new id. Which case a run meets depends on
    the allocator. The fix's proof is the host test `test_reload` and its mutant. The engine run shows that nothing
    else changes and that nothing rebuilds on every frame.
- A first try set `r_presentation` in a script run after start-up. The renderer reads it only at start-up and at
  `vid_restart`, so both sides ran stock.
