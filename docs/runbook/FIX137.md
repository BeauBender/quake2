# FIX137: the collision model bounds a leaf's cluster and every visibility offset

`CM_ClusterPVS` and `CM_ClusterPHS` (`src/common/collision.c`) indexed the visibility lump's offset
table with a leaf's cluster, which comes from the map and was checked only against -1, and
`CMod_LoadVisibility` checked neither the lump's cluster count nor its offsets. FIX137 bounds them
as the renderers' `Mod_CheckVis` and `Mod_CheckLeafs` do:

- `CMod_LoadVisibility` refuses, with `Com_Error(ERR_DROP)` and the map's name, a lump of 1 to 3
  bytes, a cluster count outside `0..MAX_MAP_LEAFS` or larger than `(filelen - 4) / 8`, and a PVS
  or PHS offset outside `0..filelen`;
- `CM_LoadMap`, once the lump is read (the leaves load first), refuses a leaf whose cluster is
  below -1, with or without visibility (round 2), or, on a map with visibility, not below the
  lump's count (`CMod_CheckLeafClusters`); without visibility a cluster of 0 or more is not
  bounded, since every row but -1's is then all visible;
- `CM_ClusterPVS` and `CM_ClusterPHS` answer a cluster the lump has no offsets for with the no-vis
  row (all visible), and check the offset against the lump before they form the input pointer
  (round 2, `CM_ClusterVisInput`).

`numclusters`, which `CM_NumClusters` reports to the server, is still raised by the leaves; with
the leaf check it can no longer exceed the lump's count. The unit cases are the nine `cmvis_*`
cases in `tests/unit/test_bspgraph.c` (eight from round 1, `cmvis_offset_at_lump_edges` from
round 2) and the renderer side's `bspcheck_leaf_cluster_below_minus_one_no_vis`.

## Round 2

The review found one more out-of-bounds read and an untested edge.

- **A cluster below -1 on a map without visibility.** `CMod_CheckLeafClusters` returned early
  without visibility, so a leaf with a cluster of -2 to -32768 loaded. `SV_LinkEdict` skips only
  -1 and stores the cluster in the entity's `clusternums`, and `SV_BuildClientFrame` (the fat PVS
  and the beam path's PHS) and `CM_HeadnodeVisible` index a row by `cluster >> 3`, up to 4 KiB
  before it. A cluster below -1 is now refused with or without visibility; the bound against the
  lump's count stays visibility-only. The renderers' `Mod_CheckLeafs` (FIX134) had the same gap
  and now refuses the same leaves, so the two sides agree. `cmvis_no_vis_any_cluster` now loads a
  no-vis map with cluster 7 and refuses -2 and -32768, and
  `bspcheck_leaf_cluster_below_minus_one_no_vis` is the renderer side's case.
- **The inclusive offset edges.** `cmvis_offset_at_lump_edges` loads a PVS offset of 0 (the
  count's own bytes, decoded as the row byte 0x02) and a PHS offset equal to the lump's length
  (no input: all visible), so a `>=` or `<= 0` tightening of the load check fails it.
- **The `in < map_visibility` guard is replaced.** `CM_DecompressVis` could not reach it, and a
  comparison of a pointer outside its object is undefined. `CM_ClusterPVS` and `CM_ClusterPHS`
  now get their input from `CM_ClusterVisInput`, which checks the offset against the lump before
  the pointer is formed (the load check has already refused one outside it, so this is defence in
  depth with no case of its own), and the comparison is gone from `CM_DecompressVis`.
