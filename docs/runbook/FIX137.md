# FIX137: the collision model bounds a leaf's cluster and every visibility offset

`CM_ClusterPVS` and `CM_ClusterPHS` (`src/common/collision.c`) indexed the visibility lump's offset
table with a leaf's cluster, which comes from the map and was checked only against -1, and
`CMod_LoadVisibility` checked neither the lump's cluster count nor its offsets. FIX137 bounds them
as the renderers' `Mod_CheckVis` and `Mod_CheckLeafs` do:

- `CMod_LoadVisibility` refuses, with `Com_Error(ERR_DROP)` and the map's name, a lump of 1 to 3
  bytes, a cluster count outside `0..MAX_MAP_LEAFS` or larger than `(filelen - 4) / 8`, and a PVS
  or PHS offset outside `0..filelen`;
- `CM_LoadMap`, once the lump is read (the leaves load first), refuses a leaf whose cluster is
  neither -1 nor below the lump's count (`CMod_CheckLeafClusters`); a map without visibility is not
  checked, since every row but -1's is then all visible;
- `CM_ClusterPVS` and `CM_ClusterPHS` answer a cluster the lump has no offsets for with the no-vis
  row (all visible), and `CM_DecompressVis` treats input before `map_visibility` as input that ran
  out.

`numclusters`, which `CM_NumClusters` reports to the server, is still raised by the leaves; with
the leaf check it can no longer exceed the lump's count. The unit cases are `cmvis_*` in
`tests/unit/test_bspgraph.c`.

## Stock maps

A host harness, kept outside the repository, links one `collision.c` with `shared.c` and stubs for
the filesystem and the console. It reads every `maps/*.bsp` out of the paks under `<datadir>` into
memory (never to disk), runs `CM_LoadMap` on it, and prints the cluster count and a hash of every
cluster's PVS and PHS row (and of cluster -1's). It was built twice, with main's `collision.c` and
with the branch's, and the two outputs compared with `cmp`.

| Pak | Maps | Refused | Rows (PVS and PHS) |
|---|---|---|---|
| `baseq2/pak0.pak` | 39 | 0 | 124016 |
| `baseq2/pak1.pak` | 8 | 0 | 16034 |
| `baseq2/pak2.pak` | 0 | 0 | 0 |
| `xatrix/pak0.pak` | 25 | 0 | 113770 |
| `rogue/pak0.pak` | 32 | 0 | 95534 |
| `ctf/pak0.pak` | 5 | 0 | 13902 |

Both builds ended `TOTAL 109 maps, 0 refused, 363256 rows`, and their outputs are identical: every
map loads, with the same cluster count and the same PVS and PHS rows for every cluster.
