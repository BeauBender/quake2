# FIX131: ios-sim.sh stops an interrupted bounded call's child, and its selftest hangs the first launcher read too

TASK180's review (round 2, the security pass) traced two gaps in `scripts/ios-sim.sh`, fixed here.

1. `bounded` runs its command as an async child and stops it only on its own timeout. A TERM, HUP or INT during a
   bounded call ran the trap's `exit 1`, and `cleanup` stopped only the launch client (`$lpid`), so the bounded
   child (for example the launcher's `xcrun simctl spawn ... launchctl list`) ran on after the script exited.
2. Only the second launcher read (the check) had a hang case (the fake's `hang2`). Both reads go through one call
   site today, but a later split of it would not be caught for the first read.

## The probe

A trap or process-group change is probed first. The probe is a script run as `bash probe.sh`, a non-interactive
bash as `ios-sim.sh` is. It reads the dispositions with python3's `signal.getsignal` (in the foreground child,
python3 installs its own INT handler when INT is at the default, so "caught" means the default was inherited). It
then reproduces the leak with main's own `bounded` (the function copied from main), main's traps
(`trap cleanup EXIT; trap 'exit 1' INT TERM`) and a `cleanup` that stops nothing else, around `sleep 120`: the
signal goes to the script, and the bounded child is looked for 2 s after the script is gone. On this host
(macOS 27.2, `/bin/bash` 3.2.57):

```
bash: 3.2.57(1)-release, interactive: no
foreground child: INT=caught TERM=default HUP=default
async child:      INT=ignored TERM=default HUP=default
async child of a script started async: INT=ignored TERM=default HUP=default
TERM: the script exited
TERM: the bounded child 92438 still runs 2 s later: LEAK
INT: the script did not exit in 5 s (the signal is ignored in a script started async)
INT: the bounded child 97251 still runs 2 s later: LEAK
HUP: the script exited
HUP: the bounded child 15837 still runs 2 s later: LEAK
INT (reset): the script exited
INT (reset): the bounded child 34063 still runs 2 s later: LEAK
```

So a non-interactive bash starts its async children with SIGINT ignored: the bounded child never sees a Ctrl-C,
and a script that is itself started async (as the selftest starts it) cannot be reached by INT at all. With SIGINT
reset to the default before the script starts (the last two lines: what a terminal's foreground job has), INT
reaches the trap, and the child still leaks. TERM and HUP are at the default in the child, but nothing sends them.
HUP had no trap; bash 3.2 still ran the EXIT trap on it (the selftest's run log shows cleanup's launcher line), but
the script ended by the signal.

## The fix

`bounded` records its child's PID in the global `bounded_pid` once it starts it, and clears it when the child has
been reaped (on its timeout and on its normal end). `cleanup` first stops that PID, by its own PID only, with
`stop_pid` (TERM, up to 5 s of grace, then KILL and reap), and clears it, before its own bounded calls (the
launcher line, the device's shutdown and delete) can reuse the global. No pattern and no process group is
signalled. HUP now goes to the same `exit 1` trap as INT and TERM.

## Selftest

- `launcher-term-stops-read`, `launcher-hup-stops-read`, `launcher-int-stops-read` (`st_signal`): the smoke, with
  its first launcher read hung (the fake's new `hang1` outcome), is sent the signal once the hung read has started;
  the script must exit within 20 s and not with 0, its device must be deleted, and the read's child must be gone
  3 s after the script exited. For INT the script is started through python3 with SIGINT reset to the default
  first. The case is skipped, with its reason, only when that reset did not take (python3 writes the disposition it
  left before it execs the script); when INT was deliverable and was not sent, the case fails rather than skips.
- `launcher-baseline-hangs` (`hang1`, `ST_OUTER=150` as `launcher-check-hangs`): the first read requires
  `timed out after 30 s: xcrun simctl spawn` and `launcher: unknown (launchctl list failed in the device)`, and the
  fake saw one read only.
