# FIX222: the denoisers' history-weight tests go through integer helpers

## Why

- The Metal shaders build with fast math. Metal compiles a float compare as `fcmp fast`, and fast math
  includes `nnan`: the compiler may assume no NaN comes. So a NaN can pass a compare written so that a NaN
  fails, and the `!(x > 0.0f)` form does not help.
- FIX219 (#826) moved every G-buffer depth and normal alpha compare onto the integer helpers of FIX212 and
  FIX213. Its correctness review found the same class on another input: the history texture's weight lane,
  the sample count the denoisers read from the temporal kernels' history (`hc.w`, `hn.w`, and RT-primary's
  `h.a`).
- No input that makes a NaN history weight has been found. This is a robustness gap, not an observed bug.

## What changed

- **One helper for the count's range.** `mtl_rtd_counted(n)` in `common/mtl_rtd_math.h` is 1 when `n` is
  in `[MTL_RTD_COUNT_FULL, MTL_RTD_COUNT_NONE)`, `[1, 16)`: the counts whose strength is above 0. It tests
  the pattern through FIX212's `MTL_RTT_BITS` (`common/mtl_rtt_math.h`, which `mtl_rtd_math.h` now
  includes) against `MTL_RTD_BITS_FULL` (`0x3f800000u`) and `MTL_RTD_BITS_NONE` (`0x41800000u`). The
  patterns of the positive numbers are ordered as the numbers, so `[1, 16)` is one range of patterns; every
  negative value has the sign bit and lies above it, and every NaN lies above `+inf`.
- **The sites.** `mtl_rtd_strength`'s range is `if (!mtl_rtd_counted(n))`; `mtl_rtd_result`'s
  `!(s > 0.0f)` is `!mtl_rtd_counted(n)` (the strength is above 0 just when the count is counted: below
  16, `16 - n` is at least `2^-20`, and so is the strength over 15); `mtl_rtpd_on` is
  `world && mtl_rtd_counted(n)`; and each kernel's `!(mtl_rtd_strength(hc.w) > 0.0f)` is
  `!mtl_rtd_counted(hc.w)`. `mtl_rtd_weight`'s `!(cn >= 1.0f)` is FIX212's `!mtl_rtt_atleast1(cn)`
  (`>= 1`, `+inf` included). No new threshold; nothing else in a kernel moves.
- **The answer.** On every pattern that is not a NaN, `-0`, the subnormals and the infinities included,
  each test gives main's float answer and each function main's value bit for bit. A NaN of either sign is
  not counted, has strength 0, weighs 0 as a neighbour, and leaves the pixel's value as it was. So every
  denoiser filters the pixels and takes the neighbours it took before, unless a NaN is in the history.

## The host tests (acceptance line 2)

`tests/metal/rm_rtdenoise_test.c` (`test_history_weight`) takes FIX219's shared edges
(`tests/metal/rm_gbuf_edges.h`, which refuses fast math so the references are IEEE compares) and seven
more: 2, 8.5, 15, the largest float below 16, 16, the smallest float above 16, and 255. For each, and for
the 2^12-stride sweep (every 2^12th pattern, 2^20 of them), against main's float code compiled in the
test (`hw_ref_strength`, `hw_ref_result`):

- `mtl_rtd_counted` equals `hw_ref_strength(n) > 0.0f` and `(n >= 1.0f) && (n < 16.0f)`;
- `mtl_rtd_strength` equals main's strength bit for bit;
- `mtl_rtd_weight`'s neighbour weight is the full weight bit for bit where `cn >= 1.0f`, and 0 elsewhere;
- `mtl_rtd_result` equals main's result bit for bit;
- and for a NaN: not counted, strength `0x00000000`, weight 0, the value kept bit for bit.

`MTL_RTD_BITS_FULL` and `MTL_RTD_BITS_NONE` are checked to be the patterns of 1 and 16.
`tests/metal/rm_rtpdenoise_test.c` (`test_on_edges`) tests `mtl_rtpd_on` over the same edges, the floats
beside 16 and the sweep: a world pixel is written just where `1 <= n < 16`, never for a NaN, and no pixel
that is not a world pixel is written.

## The guard (acceptance line 3)

Segment 7.98 of `tests/check-ref-metal.sh`, beside FIX219's 7.97, reads 20 files as text, with comments and
literals blanked and the template arguments of `as_type`, `static_cast`, `texture*`, `depth*`, `vec` and
`array` removed: every `.metal` file under `src/client/refresh/metal/`, and `common/mtl_rtd_math.h` and
`common/mtl_rtpd_math.h`.

- **The rule.** No `<`, `>`, `<=` or `>=` has a history weight on either side, against anything: a literal,
  a macro or a variable. A history weight is a `.w` or `.a` of `hc`, `hn` or `hl` (the names the denoisers
  and the temporal kernels give a history read) or of a `hist.read(...)`, or a `mtl_rtd_strength(...)`. The
  name may sit in parentheses, behind a `(float)` or `(half)` cast or inside `float(...)` or `half(...)`,
  and a `.read(...)` or the strength's call may hold one level of nested parentheses.
- **The header pins.** The count reaches the headers as a parameter (`n`, `cn`), too short a name for the
  rule, so each function is pinned alone: `mtl_rtd_counted` is the integer test of its pattern (and does
  not compare `n`), the two bit constants are the patterns of 1 and 16, and `mtl_rtd_strength`,
  `mtl_rtd_weight`, `mtl_rtd_result` and `mtl_rtpd_on` test the count with their helper and compare
  neither the count, nor `s`, nor a `mtl_rtd_strength(...)`.
- **What it cannot see.** Out of scope, by design: a history held under another name (`h` is also the
  homogeneous point in `rm_rtmodel.metal`, so it is not read; the kernels that name a history `h` pass its
  `.w` only to FIX212's helpers), a compare split across lines, `step()` and `select()`, and
  `mtl_rtt_count`'s `hcount + 1.0f < MTL_RTT_COUNT_MAX`, behind `mtl_rtt_atleast1`.
- Each failure prints its own line: `hw: a float compare of a history weight in <file>`,
  `hw: <function> does not test its count with <helper> alone`, or `hw: mtl_rtd_counted is not the
  integer test of its pattern`. On main's tree (`c8ceeaf5`) it prints 9 lines: the three files of the
  inventory (`common/mtl_rtpd_math.h`, `rm_rtdenoise.metal`, `rm_rtsun.metal`), the four header functions,
  and `mtl_rtd_counted` and its constants, which main does not have.
