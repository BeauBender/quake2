# FIX213: RT-primary's world-pixel test under Metal's fast math

## What changed

- `mtl_rtp_world` in `src/client/refresh/metal/common/mtl_rtp_math.h` decided a world pixel with two
  float compares, `depth < 1.0f` and `normal_a > 0.5f`. The Metal shaders build with fast math, so
  both compiled as `fcmp fast`, and fast math includes `nnan`: the compiler may assume no NaN comes,
  so a NaN depth or normal alpha could be folded into a world pixel. No input that makes a NaN there
  has been found. This is a robustness gap, not an observed bug.
- The two compares are now integer tests of the float's bit pattern, through FIX212's `MTL_RTT_BITS`,
  `MTL_RTT_BITS_1`, `MTL_RTT_BITS_INF` and `MTL_RTT_SIGN` (`common/mtl_rtt_math.h`, unchanged). Two
  helpers in the same style sit beside `mtl_rtp_world`, with the pattern of 0.5 as
  `MTL_RTP_BITS_HALF`:
  - `mtl_rtp_below1(f)`: `f < 1`. A non-negative pattern below that of 1, or any pattern with the
    sign set up to that of -inf (every negative value, -0 and -inf).
  - `mtl_rtp_above_half(f)`: `f > 0.5`. A pattern above that of 0.5, up to that of +inf.
- A NaN of either sign fails both, so a NaN depth or normal alpha is not a world pixel. On every
  other input, -0 and the infinities included, the answer is the float compare's. The material
  test is unchanged.
- The helpers are in `mtl_rtp_math.h`, not `mtl_rtt_math.h`, because the card's file list names that
  header alone. They use only FIX212's macros.
- Both kernels that call `mtl_rtp_world` take the change: `rm_rtptemporal.metal` (the accumulation)
  and `rm_rtpdenoise.metal` (the filter's test of the centre pixel).

## The proof

### The host test

`tests/metal/rm_rtptemporal_test.c` has two new parts, `test_world_edges` and `test_world_sweep`. The
reference is the old float compare, `ref_world`. The test is compiled without fast math, and an
`#error` refuses a build that defines `__FAST_MATH__`. Every input with no NaN is compared with
`ref_world`, and with `depth < 1.0f` and `normal_a > 0.5f` for each helper. An input that holds a
NaN must be refused, by the helper for that input. Every verdict must also equal the material test
and the two helpers combined.

The edges and their verdicts (1 means a world pixel). The depth edges use a normal alpha of 1.0 and
the world material. The normal alpha edges use a depth of 0.5.

The material is tested as before: the five material ids, each crossed with every depth edge and
every normal alpha edge. Only the world material is ever a world pixel.

The sweep takes every 2^12th pattern of each input (2^20 patterns). It crosses each pattern with
every edge of the other input: 2^20 x (14 + 12) = 27262976 inputs, 0 wrong.

On a red commit (`e5b599fc`), the test does not compile, because `mtl_rtp_below1` and
`mtl_rtp_above_half` are undeclared. With the change it prints `rm_rtptemporal_test: 658 checks, 0
failed`. Review round 1 added the three NaN edges to each table above (the reviewer's mutant, a negative bound widened by `0xfff`, passed the 658 checks); the test now runs 1015 checks (`check-ref-metal` on this round: ok, 13162 checks, 0 failed; RT-primary temporal 1015 checks, 0 failed). The reference compares are refused under `-ffast-math` and under `-ffinite-math-only`.

### The pin and its mutants

`tests/check-ref-metal.sh` extends FIX212's pin (segment 7.7) with `rtw_why`. It reads the header
as text, with comments and literals blanked, and checks these things:

- `mtl_rtp_world` returns the material test and the two helpers.
- `MTL_RTP_BITS_HALF` is `0x3f000000u`.
- Each helper reads the bit pattern, and its integer test appears once.
- The header holds no float compare against 1.0 or 0.5.

Each failed pin prints its own line. There are three mutants, and each one restores a float
compare. Each mutant must compile as C and pass the host test: without fast math the compare gives
the same answers, so only the pin can see the mutant. Each mutant must be refused by its own line,
not by a failure alone.

| Mutant | What it restores | The line that refuses it |
|---|---|---|
| `world` | the whole old line, `(depth < 1.0f) && (normal_a > 0.5f)` | `rtw: a float compare of the depth (< 1.0f)` and `rtw: a float compare of the normal alpha (> 0.5f)` |
| `worlddepth` | `(depth < 1.0f)` | `rtw: a float compare of the depth (< 1.0f)` |
| `worldnormal` | `(normal_a > 0.5f)` | `rtw: a float compare of the normal alpha (> 0.5f)` |

Segment 7.7's line now also reports `the world-pixel test as integer tests with 3 float-compare
mutants refused by their own lines`.

### Fast math: the shaders' LLVM IR

Each shader was compiled with `xcrun -sdk macosx metal -S -emit-llvm -c <kernel>.metal`, run in
`src/client/refresh/metal` as the Makefile compiles it. This uses no GPU, and it ran under the
timing lock.

Before (main `d93444d3`), the world test in `rm_rtptemporal.ll` was:

```
%34 = fcmp fast uge float %27, 1.000000e+00
%36 = fcmp fast ule float %32, 5.000000e-01
```

and in `rm_rtpdenoise.ll`:

```
%29 = fcmp fast uge float %26, 1.000000e+00
%31 = fcmp fast ule float %27, 5.000000e-01
```

After, in `rm_rtptemporal.ll` (`rm_rtpdenoise.ll` is the same, with other register numbers):

```
%34 = bitcast float %27 to i32
%35 = icmp ult i32 %34, 1065353216
%36 = icmp slt i32 %34, -8388607
%37 = bitcast <4 x float> %33 to <4 x i32>
%38 = extractelement <4 x i32> %37, i64 3
%39 = add i32 %38, -1056964609
%40 = icmp ult i32 %39, 1082130432
%41 = or i1 %35, %36
%42 = and i1 %41, %40
```

`1065353216` is `0x3f800000`. A signed compare below `-8388607` is a pattern with the sign set, up to
`0xff800000`. The add and the unsigned compare hold a pattern in `[0x3f000001, 0x7f800000]`. The
fcmp counts went from 5 to 3 in `rm_rtptemporal` (the 3 left are the blend's `alpha < w`), and from
14 to 12 in `rm_rtpdenoise`.

### Outside this card

`rm_rtpdenoise.ll` still holds `fcmp fast` compares from `common/mtl_rtpd_math.h`, the filter's own
rule. One of them is the neighbour's normal alpha test, `if (!(nn_a > 0.5f))`. That header is not
in this card's file list, so it is left as it is and reported. FIX219 (#826) is now the class card for every G-buffer depth and normal compare.
