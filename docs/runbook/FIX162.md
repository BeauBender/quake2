# FIX162: a guard for the bind call sites in cl_keyboard.c

The unit suite links the real `q2ded` objects and a few client files, but not
`src/client/cl_keyboard.c`, which needs the input, menu and video layers. FIX156
([its runbook](FIX156.md)) and the key-index fix put their safe form at call sites in that file, so
a revert there would pass `make test`. `tests/check-keyboard-sites.sh` holds them as source rules
over the real file; it needs no game data and runs in CI through `tests/ci-checks.txt`.

## The rules

Each rule reads a copy of the file with comments removed and white space collapsed, so a reformat
passes and a revert fails.

1. No `Cbuf_AddText(keybindings[` anywhere in the file. `Key_Event` makes four
   `Key_AddBindingText` calls (release, `+` press, plain press, its newline) and none of its
   `Cbuf_AddText` calls take `kb`, `cmd` or `keybindings`.
2. `Key_WriteBindings` calls `Key_WriteBindingLines(f)` and does not use `keybindings`, a `"bind`
   literal or `Key_KeynumToString`.
3. `Key_Unbindall_f` calls `Key_UnbindAll()`.
4. `Key_StringToKeynum` returns `(unsigned char)str[0]` for a one-character name, so a byte of 0x80
   or above is not a negative index.
5. `Key_Bind_f` and `Key_Unbind_f` refuse `b < 0` and `b >= K_LAST`.

## Mutants

The check copies the file 13 times, reverts one form in each copy (each `Key_AddBindingText` call
to `Cbuf_AddText`, a stray `Cbuf_AddText(keybindings[`, `Key_WriteBindingLines` replaced by
nothing or by an inline bind line, `Key_UnbindAll` removed, the cast removed, each of the four
bounds halves removed) and requires every copy to be refused. It prints the count,
`13 mutants refused`. A mutant that leaves the file unchanged also fails, so a sed that stops
matching after a refactor is noticed.

## Limits

These are text rules, not a run of the code: they hold the shape of each call site, not what the
helpers do (that is in the unit suite, through `keybind.c`). A new site that queues bound text some
other way is not seen until a rule is added for it.
