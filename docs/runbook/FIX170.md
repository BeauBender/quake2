# FIX170: FS_FOpenFile never opens a path outside its search paths

Cause: `FS_FOpenFile` (`src/common/filesystem.c`) stripped `./`, `//` and a leading `/` from a name but not
`..`, then joined the name onto each search directory. A server's `svc_serverdata` with `playernum == -1`
reaches `SCR_PlayCinematic` (`"video/%s"`, or `"pics/%s"` for image extensions), so a name such as
`../../../file` read a local file outside the search paths into the cinematic or image decoder. Read-only,
nothing goes back to the server, but untrusted parsers saw arbitrary local files.

The rule: `FS_NameEscapes(name)` is true when any `/`- or `\`-separated component is exactly `..`.
`FS_FOpenFile` runs it after the clean-up, so `.//../x` is refused too, and returns -1 as for a missing file
(with `*f == 0`). It logs once with `Com_DPrintf`, at most 64 bytes of the name. `a..b` and `..foo` are not
escapes. Stock game data has no `..` component, so what loads is unchanged.

Every other open of a name that can come from the network:

- `FS_LoadFile` and `FS_LoadFile2` open through `FS_FOpenFile`: covered.
- `FS_FOpenFile` has no write mode (`handle->mode = FS_READ`): nothing to check.
- The pak lookup (`FS_PackQuickSearch`) compares the name with directory entries in memory. A pak entry name is
  not a path on disk, so `..` in it opens nothing outside the pak. The loose-file join is behind the new check.
- `FS_FileInGamedir` is called from `FS_FOpenFile` only for the fixed names `maps.lst` and `players/...`
  and after the check.
- The download opens (temp and target) are gated by `CL_DownloadFilter`, which rejects `..`, a leading `.` or `/`,
  `:` and library extensions, and by `FS_CreatePath`, which refuses `..`.

Tests (`tests/unit/test_filesystem.c`, `fs_name_escape`): `../x`, `a/../../x`, `.//../x`, `a\..\x`, `a/..` and `..`
are refused although a file exists one level above the search directory; `a/b.txt`, `a..b.txt` and
`..foo/x.txt` open. `cl_cin.c` is not linked into the suite, so the cinematic path is tested through
`FS_FOpenFile` directly.
