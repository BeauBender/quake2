# FIX135: a refused model load leaves no named empty slot

`Mod_ForName` in gl1, gl3 and soft names a slot (`strcpy(mod->name, name)`), loads the file and runs
the format's loader. A loader refuses a bad model with `Com_Error(ERR_DROP)`, which longjmps: nothing
after the refusal runs, so the slot stayed named and empty (the next lookup of the same name found it
and returned an empty model) and the file buffer leaked. ref_metal already freed its unfinished slots
(`RM_FreeUnfinished`).

## Design: deferred cleanup

`Mod_ForName` records the load in progress (`Mod_LoadBegin`, `src/client/refresh/files/models.c`) and
closes it on success (`Mod_LoadEnd`). The next `Mod_ForName` or `Mod_FreeAll` calls
`Mod_ReclaimUnfinished`, which takes an unfinished load back (`Mod_LoadAbandon`): its slot goes to the
renderer's `Mod_Free`, which unmaps the hunk and clears the slot, and its file buffer to
`ri.FS_FreeFile`.

This was chosen over clearing the slot at each refusal. The refusals are spread over every loader
(BSP lumps, alias, sprite) and the shared lump readers in `files/models.c`, and a refusal added later
would have to remember the cleanup. The deferred form is one recorded pointer pair and one call at
the two entry points that can follow a refusal, and it covers every refusal, present and future.
`tests/check-bsp-loader.sh` requires each of the three renderers to call the three helpers.

## The open hunk

A BSP's hunk is begun (`Hunk_Begin`) before its lump loaders run, so a refusal there leaves it open.
`Hunk_Begin` (`src/backends/unix/shared/hunk.c`) used to write 0 as the size `Hunk_Free` unmaps, and
only `Hunk_End` wrote the real size; freeing such a hunk ended in `munmap(m, 0)`, `EINVAL` and
`Sys_Error`. That path existed before this card too (`RI_BeginRegistration` frees the old world's
slot when the next map has another name). `Hunk_Begin` now records the whole reservation, and
`Hunk_End` still overwrites it with the final size. The Windows backend releases with
`VirtualFree(base, 0, MEM_RELEASE)`, which frees the whole reservation already.

`Mod_LoadMD2` and `Mod_LoadSP2` keep their hunk in a local and refuse by returning NULL after
`Hunk_Begin`, so the caller never saw the hunk; each of those returns now frees it first.

The unit cases are `hunk_unfinished_free` and `slot_reclaim_frees_unfinished_hunk` in
`tests/unit/test_bspgraph.c`, against the real hunk code, and `slot_refused_load_is_abandoned` and
`slot_finished_load_is_kept` for the record itself.

## Follow-ups (FIX140)

- **The reclaim's position is pinned.** `tests/check-bsp-loader.sh` requires `Mod_ReclaimUnfinished` in
  each renderer's `Mod_ForName` before the first `strcmp` (the cached-name lookup: a refused load's
  named slot would otherwise come back as a cache hit) and in `Mod_FreeAll` before the free loop. A
  missing loader file fails the script. The same script requires `Mod_LoadBegin` before the first
  `FS_LoadFile` in each `Mod_ForName`, and `Mod_LoadEnd` between that `FS_LoadFile` and the miss
  branch's `return NULL`. Mutants: gl1's call moved below the lookup, a missing `sw_model.c`, gl1's
  early `Mod_LoadBegin(mod, NULL)` deleted, and gl3's `Mod_LoadEnd()` on the miss deleted.
- **The missing-file slot.** `Mod_ForName` calls `Mod_LoadBegin(mod, NULL)` right after copying the
  name, so a `Com_Error` from a missing file (`crash` set) is reclaimed like any other refusal.
  `Mod_ReclaimUnfinished` frees the file buffer only when there is one, and the non-crash miss closes
  the load with `Mod_LoadEnd`. Unit case: `slot_reclaim_missing_file_clears_name`.
- **The alias and sprite hunk on a skin refusal.** `find_image` can `Com_Error` between `Hunk_Begin`
  and the return of `Mod_LoadMD2` and `Mod_LoadSP2`, while the hunk is in a local. They record it with
  `Mod_LoadHunk(extradata)` around the skin lookups (NULL after), and `Mod_ReclaimUnfinished` frees it
  before the slot, whose `extradata` is still NULL then, so nothing is freed twice. This was chosen
  over a field in the slot (the loaders never see the slot) and over ref_metal's `RM_SkinLater`
  (which needs the renderer to register skins later). ref_metal passes `RM_SkinLater`, which never
  raises, so the record is always cleared on return there, and it still frees its own unfinished
  slots (`RM_FreeUnfinished`). Unit case: `slot_reclaim_frees_alias_hunk_on_skin_refusal`, which asks
  `mprotect` whether the hunk is still mapped. The same case runs `Mod_LoadMD2` to success with a
  `find_image` that finds an image and checks that the record is NULL on return (deleting the
  success-path `Mod_LoadHunk(NULL)` fails it).
