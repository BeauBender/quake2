# FIX219: one shared integer helper for the G-buffer world and normal tests

## Why

- The Metal shaders build with fast math. Metal compiles a float compare as `fcmp fast`, and fast math
  includes `nnan`: the compiler may assume no NaN comes. So a NaN depth or normal alpha can pass a
  compare written so that a NaN fails, and the `!(x > 0.5f)` form does not help.
- FIX212 (#805) moved the temporal history's guards to integer tests of the float's bit pattern, and
  FIX213 (#806) moved `mtl_rtp_world`. The same two rules, "the depth is short of the far plane" and
  "the normal was written", were still float compares in most of the ray-traced kernels.
- No input that makes a NaN in the G-buffer has been found. This is a robustness gap, not an observed
  bug.

## The inventory (acceptance line 1)

Found with a grep of `src/client/refresh/metal/` (every `.metal` file and `common/*.h`) for a compare of
a G-buffer depth (`depth.read`, held as `d`, `ds`, `qd` or `depth`) or normal alpha (`normal.read(...).a`,
held as `nn.a`, `ns.a`, `nv.a`, `normal_a`, `nn_a` or `a`) against a float literal, then confirmed in each
shader's LLVM IR (the `fcmp fast` counts below). Line numbers are main's, `9046347a`. The texture alpha
tests (`c.a > 0.666f` in `rm_shaders.metal` and `rm_gbuf.metal`) read a texture, not the G-buffer, and
are not listed.
