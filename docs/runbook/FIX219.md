# FIX219: one shared integer helper for the G-buffer world and normal tests

## Why

- The Metal shaders build with fast math. Metal compiles a float compare as `fcmp fast`, and fast math
  includes `nnan`: the compiler may assume no NaN comes. So a NaN depth or normal alpha can pass a
  compare written so that a NaN fails, and the `!(x > 0.5f)` form does not help.
- FIX212 (#805) moved the temporal history's guards to integer tests of the float's bit pattern, and
  FIX213 (#806) moved `mtl_rtp_world`. The same two rules, "the depth is short of the far plane" and
  "the normal was written", were still float compares in most of the ray-traced kernels.
- No input that makes a NaN in the G-buffer has been found. This is a robustness gap, not an observed
  bug.

## What changed

- **One home for the rule.** The depth and normal alpha tests are FIX213's `mtl_rtp_below1` (`f < 1`) and
  `mtl_rtp_above_half` (`f > 0.5`) in `common/mtl_rtp_math.h`, integer tests of the pattern through FIX212's
  `MTL_RTT_BITS`. Each kernel now includes that header and calls them. Including it was the smaller change:
  moving the helpers to a new header would rewrite FIX213's pin (segment 7.7 reads them in `mtl_rtp_math.h`)
  and both RT-primary kernels' includes, for no change in what the kernels compile. The header holds no
  pointer and only `static inline` functions, so a kernel that includes it compiles nothing it does not call.
- **No new threshold.** Every site's compare is one of three rules: `depth < 1`, `alpha > 0.5`, and the water
  mark's `alpha > 0`. The third is FIX212's `mtl_rtt_positive` (`f > 0`), already in `common/mtl_rtt_math.h`,
  which `common/mtl_rtw_math.h` now includes. No two rules are folded into one helper.
- **The sites.** Each compare is replaced in place, so `(d < 1.0f) && (nn.a > 0.5f)` is
  `mtl_rtp_below1(d) && mtl_rtp_above_half(nn.a)`, `!(nv.a > 0.5f)` is `!mtl_rtp_above_half(nv.a)`, and
  `!(a > 0.0f)` in `mtl_rtw_alpha_level` is `!mtl_rtt_positive(a)`. Nothing else in a kernel moves.
- **The answer.** On every input that is not a NaN, `-0` and the infinities included, each helper gives the
  float compare's answer. A NaN of either sign fails each. So every kernel's pixels and taps are the ones it
  took before, unless a NaN is in the G-buffer.

## The host tests

`tests/metal/rm_gbuf_edges.h` holds the edges the tests share, and an `#error` against `__FAST_MATH__` and
`__FINITE_MATH_ONLY__`, so the reference compares are IEEE ones. `rm_rtptemporal_test.c` tests each helper
over the edges (`test_gbuf_helpers`): the verdict wanted per edge, the float compare's answer, and a NaN
refused. Then the 2^12-stride sweep: every 2^12th pattern, 2^20 of them, against the float compare, and each
NaN refused.

| Edge | Pattern | `mtl_rtp_below1` (`< 1`) | `mtl_rtp_above_half` (`> 0.5`) | `mtl_rtt_positive` (`> 0`) |
|---|---|---|---|---|
| +0 | `0x00000000` | 1 | 0 | 0 |
| -0 | `0x80000000` | 1 | 0 | 0 |
| a negative subnormal | `0x80000001` | 1 | 0 | 0 |
| a positive subnormal | `0x00000001` | 1 | 0 | 1 |
| the next float below 0.5 | `0x3effffff` | 1 | 0 | 1 |
| 0.5 | `0x3f000000` | 1 | 0 | 1 |
| the next float above 0.5 | `0x3f000001` | 1 | 1 | 1 |
| the largest float below 1 | `0x3f7fffff` | 1 | 1 | 1 |
| 1 | `0x3f800000` | 0 | 1 | 1 |
| the smallest float above 1 | `0x3f800001` | 0 | 1 | 1 |
| -1 | `0xbf800000` | 1 | 0 | 0 |
| FLT_MAX | `0x7f7fffff` | 0 | 1 | 1 |
| +inf | `0x7f800000` | 0 | 1 | 1 |
| -inf | `0xff800000` | 1 | 0 | 0 |
| quiet NaN | `0x7fc00000` | 0, refused | 0, refused | 0, refused |
| signalling NaN | `0x7f800001` | 0, refused | 0, refused | 0, refused |
| negative NaN | `0xffc00000` | 0, refused | 0, refused | 0, refused |
| the smallest negative NaN | `0xff800001` | 0, refused | 0, refused | 0, refused |
| the largest negative NaN | `0xffffffff` | 0, refused | 0, refused | 0, refused |
| the largest positive NaN | `0x7fffffff` | 0, refused | 0, refused | 0, refused |

The three headers that call the helpers for a kernel are tested over the same edges and sweep, each against
its old compare:

- `rm_rtpdenoise_test.c`, `mtl_rtpd_weight`'s neighbour normal alpha: RT7's weight, bit for bit, where
  `nn_a > 0.5f` holds, and 0 elsewhere and for a NaN.
- `rm_rtmtemporal_test.c`, `mtl_rtmt_model`: each depth edge crossed with each normal alpha edge, and each
  sweep pattern against every edge of the other input, `(depth < 1.0f) && (normal_a > 0.5f)` or not a model
  pixel for a NaN.
- `rm_rtwater_test.c`, `mtl_rtw_alpha_level`: the old rule's level, and level 0 (no mark) for a NaN.

The kernels' own sites are Metal and have no host test; they call the same helpers.

## The guard (acceptance line 3)

Segment 7.97 of `tests/check-ref-metal.sh` reads 22 files as text, with comments and literals blanked: every
`.metal` file under `src/client/refresh/metal/`, and the four headers that test a G-buffer value for a
kernel (`common/mtl_rtp_math.h`, `mtl_rtpd_math.h`, `mtl_rtmt_math.h`, `mtl_rtw_math.h`).

- **The rule.** No `<`, `>`, `<=` or `>=` has a G-buffer name on one side and a float literal on the other,
  in either order. The depth names are `d`, `ds`, `qd`, `depth` and `depth.read(...)`, the names every kernel
  gives the G-buffer's depth. The normal alpha names are a `.a` or `.w` of a vector whose name starts with `n`
  (`nn`, `ns`, `nv`, `ncv`), `normal_a`, `nn_a` and `normal.read(...).a` or `.w`.
- **The spellings it reads.** The literal is an integer, a leading-dot, a decimal or an exponent form, with
  an `f`, `F`, `h` or `H` suffix (`1`, `.5f`, `0.5`, `1.0F`, `1e0f`, `0.5h`). The name, or the literal, may
  sit in a parenthesis or behind a `(float)` or `(half)` cast, or the name inside `half(...)`
  (`(ds) < 1.0f`, `ds < (float)1`, `half(nn.a) > 0.5h`). A `.read(...)` may hold one level of nested
  parentheses (`depth.read(uint2(x, y)) < 1.0f`). A literal written first needs a non-identifier character
  before it, so `x1 > d` is not a compare against a literal.
- **One more pin.** `mtl_rtw_alpha_level`'s alpha is the parameter `a`, too short a name for the rule, so
  that function is pinned alone: it must test `a` with `mtl_rtt_positive` and with no float compare.
- **What it cannot see.** Out of scope, by design: a compare against a variable (`d < far`), `step()` and
  `select()` with a variable, and a depth or normal alpha held under a name other than the ones above. The
  names are the ones every kernel uses today, so a new kernel should keep to them. The history's `.w`
  (`hc.w`, `h.w`) is not a G-buffer value and is not read.
- Each failure prints its own line, naming the file and the kind: `gbf: a float compare of a G-buffer depth
  in <file>` or `gbf: a float compare of a G-buffer normal alpha in <file>`. On the red commit (`5fdde709`)
  it printed 17 lines, one for each file and kind in the inventory, plus the alpha level's line.

Each mutant puts back one compare. Its target must be in its file exactly once, and the mutant must be
refused by its own line, not by a failure alone. The kernel mutants restore main's text, which compiled.
