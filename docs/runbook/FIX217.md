## What changed

- `Makefile`: `-MMD` is added to `CFLAGS` on every host. It was inside `ifneq ($(YQ2_OSTYPE), Darwin)`, so on
  macOS the client, server and game objects wrote no `.d` file, and `-include $(CLIENT_DEPS)` (and the server
  and game ones) read nothing. An edit to a header rebuilt `ref_metal` (its `REFMETAL_DEPFLAGS`) and kept every
  stale client object, `vidrules.o` among them.
- `tests/check-build-deps.sh`, listed in `tests/ci-checks.txt`. It runs in CI's fast group (`tests/ci-map.txt`).

## Why Darwin was left out

The condition is from the 2010 Makefile (`ce68e010`) and was only renamed since (`fcae894c`): its comment says
`-MMD` is "unsupported by the Clang shipped with OS X". That was the 2010 Xcode clang. Today's Apple clang
(21.0.0, clang-2100.4.1.1) supports it for C and Objective-C (`cc -c -MMD -arch arm64 -x objective-c a.c -o a.o`
writes `a.d` with `a.o: <SDK>/SDKSettings.json a.c h.h`); `REFMETAL_DEPFLAGS` and `SDL3_DEPFLAGS` already used it
on Darwin. Nothing else in the Darwin build needed the exception: the link lines use `LDFLAGS`, not `CFLAGS`, and
`third_party/sdl3.make` has its own flags.

## The check

`tests/check-build-deps.sh` builds nothing. From `make -n` it requires the compile line of one client object
(`vidrules.c`), one server object (`sv_main.c`) and one game object (`g_main.c`) to carry `-MMD`; the three
`-include $(..._DEPS)` lines; and `make -n -W src/client/menu/header/vidrules.h client` to name `vidrules.o`.
Mutant: a scratch Makefile with the `override CFLAGS += -MMD` line removed must fail the flag check (the
sub-makes are pointed at it with `MAKE="make -f ..."`, since the targets re-invoke `$(MAKE)`).

- Red on main: `FAIL compiled without -MMD: src/client/menu/vidrules src/server/sv_main src/game/g_main`.
- Green with the fix: all six lines `ok`, then `check-build-deps: ok`.
- The `-W` line cannot fail by itself on a tree with no objects (every object is "to build"); the flag line is the
  one that carries the invariant, and the real build below shows the `.d` doing the work.

## A real build

`make build/release/client/src/client/menu/vidrules.o` writes `vidrules.d`; with it, `make -n` says "up to date";
after `touch src/client/menu/header/vidrules.h` (restored by content, nothing edited) it names the `vidrules.c`
compile again.

## A clean build's output

`make -n` for `client server game`, `STATIC_MODULES=1 STATIC_RENDERER=soft client`, `ASAN=1 server game` and
`ios`, before and after: same line counts, and identical once every ` -MMD` is deleted from both (the added flag
is the only difference; the `ref_metal` lines already had one from `REFMETAL_DEPFLAGS`, and now carry it twice,
which clang accepts). The `STATIC_MODULES`, iOS and sanitizer rules are the same rules with the one flag added.

## Review round 1

- **B1, the check failed in a built tree.** `missing()` used `make -n` without `-B`; once the objects existed there was
  no compile line to read. Now `make -n -B`. Red first: after `make server game` and the `vidrules.o` object,
  the old check printed `FAIL compiled without -MMD: ... (no-compile-line)`. Fixed, it passes in a fresh tree and in
  that built tree; the mutant (no `-MMD -MP` line) is refused for the missing flag, not a missing line.
- **I1, `-MMD` without `-MP`.** The flag is now `override CFLAGS += -MMD -MP`, and the check requires both. Case: an
  object whose `.d` names a header, the header deleted: `make -n` stops with `No rule to make target 'h.h'` with
  `-MMD` alone and carries on (recompiles) with `-MMD -MP`.
- **`ref_soft` headers.** `REFSOFT_DEPS` was defined but never `-include`d. Added the include; the check now requires
  it and reads the compile line of `sw_main.c`.
- **Stale comments.** `scripts/test.sh` (the `-B` justification, behaviour unchanged) and the Makefile note above
  `test_imgsize.o` no longer say Darwin has no `.d` tracking.
