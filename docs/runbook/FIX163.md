# FIX163: the Keys menu's unbind cannot erase a saved bind the player did not see

FIX156 ([its runbook](FIX156.md)) keeps each key's player-written body (`keybindplayer[]`) apart from what the key runs now (`keybindings[]`), and `config.cfg` saves only the former. The Keys menu showed `keybindings[]`, so on a key a server had bound the player saw the server's command. Clearing it called `Key_SetBinding(k, "")` from the menu, which is the player's text: it wrote `""` into `keybindplayer[]` and the saved bind the player never saw was gone from `config.cfg`.

## The property

A player action in the Keys menu never erases a saved binding that the player did not see.

## The call

`Key_ClearForPlayer(k)` in `keybind.c`, used by `M_UnbindCommand`. On a key the player owns it is `Key_SetBinding(k, "")`, as before. On a key the server owns it removes only what the player saw: the key returns to `keybindplayer[k]` and is the player's again; with no saved body the key ends up unbound, as before. A key number outside the tables is ignored.

Why this and not "clear both": the menu cannot show the saved body while a server's command sits on the key, so erasing it would destroy data on a click that did not name it. Why not "leave the server's bind": the player asked for the server's command to go, and the key is theirs to take back.

`bindlist` is left as it is: marking server-owned keys is not a one-line change that is worth the output-format risk, and no doc lists its format, so nothing is added.

## Tests

In `tests/unit/test_keybind.c`: `keybind_menu_clear_restores_player_body` (player saves `a = +moveleft`, a server binds `a` to `+attack`, the helper runs: `a` is `+moveleft`, the player's, and the writer writes it), `keybind_menu_clear_player_key` (a player key becomes `""`), `keybind_menu_clear_server_key_no_player_body` (a server key with nothing saved becomes `""`, and a number outside the tables is ignored). `menu.c` is not linked into the suite, so the helper is what is tested; `make client` builds the call.
