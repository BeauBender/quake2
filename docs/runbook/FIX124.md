# FIX124 and FIX125: the identity check refuses what it cannot read, and scans binary blobs

Two cards, one lane, both on `tests/check-no-local-identity.sh` (the gate's identity check, which
the commit hook and the push hook both run). The property for both: no tracked file, text or
binary, carries the host name, the user name or the home path to the public remote, and the
check refuses whenever it cannot read what it was asked to check. Nothing below prints a real
identity value: the self-tests use their synthetic names (`zzq-synthetic-box`, `zzquser`,
`/home/zzqhome`, and the hooks' own), and the check prints counts, paths and kinds only.

## FIX124: an unreadable index blob

`scan_repo` searched the index with `git grep --cached`. A regular file whose index blob is
missing makes `git grep` print an error and exit 1, which is also its no-match status, so the
check reported clean. (A blob whose zlib header is broken already made `git grep` die with status
128, which the check refused.)

The fix: before the word searches, the id of every index entry but gitlinks goes to
`git cat-file --batch-check`, which prints `<id> missing` for an object it cannot find or whose
header it cannot read; any line other than `blob <id>` refuses (status 2, "the scan could not
run"). Stderr is not judged: with an alternate object directory that does not exist (as
`tests/check-identity-env.sh` sets one) both `git cat-file` and `git grep` warn on stderr about
an index that is fully readable, and a first version of the fix that refused any word on stderr
failed that check.

## FIX125: binary blobs

The check already read every blob with `git grep -a`, and then dropped each hit in a blob that
held a NUL byte, so one leading NUL took the home path past both hooks. Debug Mach-O objects,
static archives, `.metallib` files and dSYM bundles carry absolute source paths.

The fix: the NUL skip is gone. A binary blob is scanned like text, as bytes: the host name and the
home path as fixed substrings, the user name as a whole word or path component (`git grep -w`,
lines split at newlines; a NUL is not a word character, so `\0/srv/<user>/` matches and
`<user>ful` does not). Each hit's path is still checked to name an index entry
(`git cat-file -e :0:<path>`), so a path printed in a form the loop cannot read back refuses as
before. The commit hook's build-output filter and `.gitignore` gain `*.a`, `*.metallib` and
`*.dSYM/`.
