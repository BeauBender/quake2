# FIX115: the gate's invariants in CI, required checks, and skips that must not pass

Review findings AR-01 and AR-02 ([the 2026-11-17 review](../reviews/2026-11-17-fork-window.md)):
CI ran the build, the unit tests, `tests/check-static-modules.sh --full`, `tests/check-ios.sh`
and coverage, but none of the other `tests/check-*.sh`, so those invariants held only on the host
that ran the gate; `main-protect` required no status check; and a check whose host tool was
missing printed a skip line and passed, so a green run covered only what the host happened to have.

## What changed

- **`invariants_macos`**, a new job of `.github/workflows/macos.yml` on the free standard
  `macos-latest` runner. It checks out the full history (`fetch-depth: 0`:
  `tests/check-cvar-docs.sh` reads the upstream base commit and fails on a shallow clone) and runs
  `scripts/ci-checks.sh`: every check named in `tests/ci-checks.txt`, through
  `scripts/gate-checks.sh`, the scheduler the gate uses, two at a time. No new action and no new
  pin: it reuses the build job's `actions/checkout` pin. `tests/check-ios.sh` moved from the build
  job into it, so it runs once.
- **`tests/ci-local-only.txt`**: the checks that run on the build host's gate only, one
  `name: reason` per line (below).
- **A `<NAME>_REQUIRE=1` for every skip** in `tests/check-*.sh` (below): set, the skip fails the
  check with a line that names the variable; unset, every check behaves as before.
- **`tests/check-ci-parity.sh`**, in the gate by the `tests/check-*.sh` glob and in CI through the
  list. It fails when a check is in neither list (or in both, or a list names no check, or a
  local-only entry has no reason), when a skip line has no `_REQUIRE` within the five lines before
  it, and when no job runs `scripts/ci-checks.sh` or such a job checks out shallow or does not set
  `CHECK_IOS_REQUIRE: 1`. A skip line is an `echo` or `printf` at the start of a statement whose
  text holds `skipped:`, or holds `skip` with `exit 0` on that line or the next. Its self-test
  refuses eight mutants on scratch copies (never the real tree): an unlisted `tests/check-x.sh`, a
  listed check with a skip and `exit 0` and no `_REQUIRE` (two spellings), a local-only entry with
  no reason, a name in both lists, the invariants job without `fetch-depth: 0`, without
  `CHECK_IOS_REQUIRE`, and no job running `scripts/ci-checks.sh`.
- **The build host's gate** (`scripts/test.sh`) sets `CHECK_REF_METAL_REQUIRE=1` and
  `CHECK_METAL_SHIM_REQUIRE=1` on macOS when `xcrun -f metal` finds the Metal compiler (the test
  both checks use), unless the environment names them already; a host without it still runs both
  checks, with the build skipped and said.
- **`.github/rulesets/main-protect.json`** requires the status checks `build_macos_aarch64 (macos)`
  and `invariants_macos` from GitHub Actions (app id 15368, read from the check runs of a main
  commit).

`check-workflow-pins.sh` one are the extra four). The colour-space probe has a variable of its own
because it needs a Metal device, which a host with the Metal compiler may lack, and the gate sets
only the compiler ones.

CI sets `CHECK_IOS_REQUIRE`, `CHECK_EVIDENCE_REQUIRE`, `CHECK_AUTORELEASE_POOL_REQUIRE`,
`CHECK_STATIC_MODULES_REQUIRE` and `CHECK_BENCH_REQUIRE`: the image is macOS with Xcode (the build
compiles with cc), the iOS simulator and device objects of `tests/check-ios.sh` were built there
before this card (its log: 180 objects for the simulator, 180 for a device), and python3 is in that
check's tool list. Not set there: the tvOS and visionOS SDKs, a Metal compiler and device,
`leaks(1)` and the VideoToolbox model, none of which the workflow has shown.

## The local-only checks

- `check-no-local-identity.sh`: it guards the names of the host that commits. On the runner the
  user name is `runner`, a word the tracked text uses in prose, so it would fail there on words
  that name no host.
- `check-identity-env.sh`: **unverified on runner**; it runs the identity check and the hooks with
  the host's real user and host names beside made-up ones.
