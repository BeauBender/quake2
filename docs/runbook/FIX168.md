# FIX168: server-written cvars, what FIX158 left

FIX158 ([its runbook](FIX158.md)) marks a cvar whose value a server line wrote, and
`Cvar_WriteVariables` skipped every marked cvar. This card closes three things it left open. The
property: **no value a server wrote becomes the player's, or is saved as the player's, except by
the player writing a different value from text.** No `cvar_t`, protocol, savegame or config format
change, and no new cvar or command.

## 1. The kept value: dropped

Round 1 of this card kept the value a cvar held before a server's first write and wrote it to
`config.cfg`. Review found three holes and it was removed. `Cvar_WriteVariables` is FIX158's again:
`if (Cvar_ServerWrote(var->name)) continue;`. A marked cvar's earlier saved value is dropped, and the
next start uses the default (a cost FIX158 lists). The three holes:

- **B1 (security):** the kept value could be a string the engine had copied from the network (the
  `game` cvar in `CL_ParseServerData`, which can hold a newline), and `config.cfg` then split it into
  the player's lines.
- **I1 (security):** on a latched cvar the kept value could become a value a server chose.
- **I2 (security):** a server's archive flag made the client save a value the player had set on a
  cvar that was not archived, for example `rcon_password`, in plaintext.

The three probes stay as regressions (`cvar_rvsec_*` in `tests/unit/test_cvar_source.c`) and pass
with the skip. The mark entry (`cvar_servermark_t`) holds only the name again.

## 2. `reset` and `resetall`

`Cvar_AddToList` takes a created cvar's value as its `default_string`, so for a cvar a server line
created, the default is the server's. A private list of names, `cvar_serverdefaults`, records the
cvars a server line created (`Cvar_NoteCreated`, from `Cvar_Set2` and `Cvar_FullSet`). It outlives
the mark, holds each name once and a cvar is never removed, so it is bounded by the cvar count, and
`Cvar_FreeList` frees it. `Cvar_ResetVar`, which `reset` and `resetall` now call, does the
`Cvar_SetVar`, and if the reset changed the value, the cvar has a server-created default, no mark
exists and the value is now that default, it adds a mark. The file then omits
the cvar, and `vstr` and `$` run it as the server's. A reset that changes nothing changes no owner.

The entry also holds the value that created the cvar. A server line can create a cvar before the
engine registers it, and `Cvar_Get` then replaces `default_string` while the name stays in the list.
`Cvar_ResetVar` marks only while that stored value still equals `var->default_string`, so a reset to
the engine's own default is the player's (`cvar_rv168_stale_server_default`).

A server-created cvar that the player wrote earlier, then reset, ends marked. The
player's value is gone because the reset replaced it, and the value now held is the server's.

## 3. The latched edge: accepted

A latched write while a server is running keeps the old value in `var->string` until
`Cvar_GetLatchedVars`. If the old live value was a server's and the player's latched write clears the
mark, `vstr` and `$` run the live value, the server's, as the player's until then. Closing it needs
a second state per cvar (a pending owner for the latched value, kept apart from the live one) and
the latch application to move it. That is more than a small change at the latched branch, so it is
accepted. The window is the time between the player's latched write and the next map load, it
starts only from a player action, and the value ran is one a server already had running as its own
before. Nothing here changes it. The same holds for `reset`: a `reset` of a latched cvar while a server
runs leaves the live value as the player's until the latch applies.

## 4. `RTPreset_Save`

`RTPreset_Save` (`src/client/menu/rtpreset.c`) skips a cvar for which `Cvar_ServerWrote` is true.
Skipping matches the file writer without a new prototype, and a preset that
omits a line leaves that cvar alone on load.

## Tests and proof

In `tests/unit/test_cvar_source.c`:

- `cvar_fix168_file_omits_marked_until_player_writes` (was `..._keeps_players_earlier_value`): the
  file omits the marked cvar and the server-created one; once the player writes `Q`, the file holds
  `Q`.
- `cvar_rvsec_engine_then_server_newline_not_written`, `cvar_rvsec_latched_server_value_not_written`,
  `cvar_rvsec_server_archive_flag_not_written`: the round 1 security probes (B1, I1, I2).
- `cvar_fix168_reset_to_server_default_stays_marked`: uses `reset` on the named cvar, not `resetall`,
  which would reset every cvar of the shared test process.
- `cvar_rv168_stale_server_default`: the stale-default case above.
- `cvar_fix168_rt_preset_save_skips_marked`: restores the cvar table and preset directory before any
  failing check (as `RTP_REQUIRE` in `test_rtpreset.c`), frees the detached cvar and removes the file.

Red on `386a928f` plus the new tests: the file test, the three probes and the stale-default test
fail. Proof lines for the final head are in the card's report.
