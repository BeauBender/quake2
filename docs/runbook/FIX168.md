# FIX168: server-written cvars, what FIX158 left

FIX158 ([its runbook](FIX158.md)) marks a cvar whose value a server line wrote, and
`Cvar_WriteVariables` skipped every marked cvar. This card closes three things it left open. The
property: **no value a server wrote becomes the player's, or is saved as the player's, except by
the player writing a different value from text.** No `cvar_t`, protocol, savegame or config format
change, and no new cvar or command.

## 1. The player's earlier value is kept

A mark entry in `src/common/cvar.c` (`cvar_servermark_t`) now holds `kept`: the value the cvar held
just before the server's first write. `Cvar_NoteWriter` takes it as an argument, and each caller
passes it before the write frees it (`Cvar_SetVar`, the latched branch, and `Cvar_FullSet`; a cvar a
write created passes `NULL`). `Cvar_WriteVariables` writes `set x "<kept>"` for a marked cvar, and
skips the cvar if there is no kept value, that is, if the server created it. The kept value is freed
when the mark clears (`Cvar_FreeServerMark`) and in `Cvar_FreeList`.

A later server write to an already marked cvar leaves `kept` as it is: it is the player's value,
not an earlier server value. The player's write of a different value clears the mark, and the file
then holds that value. This replaces FIX158's "the earlier value is not rewritten" wording.

## 2. `reset` and `resetall`

`Cvar_AddToList` takes a created cvar's value as its `default_string`, so for a cvar a server line
created, the default is the server's. A private list of names, `cvar_serverdefaults`, records the
cvars a server line created (`Cvar_NoteCreated`, from `Cvar_Set2` and `Cvar_FullSet`). It outlives
the mark, holds each name once and a cvar is never removed, so it is bounded by the cvar count, and
`Cvar_FreeList` frees it. `Cvar_ResetVar`, which `reset` and `resetall` now call, does the
`Cvar_SetVar`, and if the reset changed the value, the cvar has a server-created default, no mark
exists and the value is now that default, it adds a mark with no kept value. The file then omits
the cvar, and `vstr` and `$` run it as the server's. A reset that changes nothing changes no owner.

A server-created cvar that the player wrote earlier, then reset, ends marked with no kept value. The
player's value is gone because the reset replaced it, and the value now held is the server's.

## 3. The latched edge: accepted

A latched write while a server is running keeps the old value in `var->string` until
`Cvar_GetLatchedVars`. If the old live value was a server's and the player's latched write clears the
mark, `vstr` and `$` run the live value, the server's, as the player's until then. Closing it needs
a second state per cvar (a pending owner for the latched value, kept apart from the live one) and
the latch application to move it. That is more than a small change at the latched branch, so it is
accepted. The window is the time between the player's latched write and the next map load, it
starts only from a player action, and the value ran is one a server already had running as its own
before. Nothing here changes it.

## 4. `RTPreset_Save`

`RTPreset_Save` (`src/client/menu/rtpreset.c`) skips a cvar for which `Cvar_ServerWrote` is true.
Skipping, not writing the kept value, matches step 1 without a new prototype, and a preset that
omits a line leaves that cvar alone on load.
