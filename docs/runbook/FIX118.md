# FIX118: one set of BSP checks for every renderer, and the stock maps that pass them

FIX118 moved ref_metal's BSP checks (`RM_CheckLumps`, `RM_CheckVis`, `RM_CheckNodes`,
`RM_CheckFaceEdges`) into `src/client/refresh/files/models.c` as `Mod_CheckLumps`,
`Mod_CheckVis`, `Mod_CheckNodes` and `Mod_CheckFaceEdges`. All four renderers' `Mod_LoadBrushModel`
(gl1, gl3, soft and metal) call them before any lump is read, and `tests/check-bsp-loader.sh` keeps
it so. The property: a map is refused the same way, with the same reason, by every renderer, and
every map that ships with the game still loads. The unit cases are in `tests/unit/test_bspgraph.c`
(`bspcheck_*`).

## Review round 2

| I2: `check-bsp-loader.sh` counted a call inside a multi-line comment or `#if 0`, and a call whose result was discarded | the loader body is read with comments stripped across lines and `#if 0` regions (nested `#if` inside them too) dropped; a check not negated into the refusal's condition is refused; three selftest mutants | 2996b30e, aed64d28 |

With the fix the suite passes (`yq2test: 406 tests, 0 failed`).

The I1 cases bite: on a scratch copy of the tree whose `Mod_CheckLumps` returns `true` right after
the lump loop, `make test TEST_ARGS=bspcheck` ends `yq2test: 9 tests, 2 failed`
(`bspcheck_texinfo_chains` and `bspcheck_lump_limits`; `bspcheck_vis_clusters_past_leafs` tests
`Mod_CheckVis` and passes).

The three new script mutants, each on a scratch copy of the loader files: gl1 with its
`Mod_CheckNodes` call inside a comment that spans two lines, soft with the call under `#if 0` after
a nested `#ifdef ... #endif`, and metal with the call moved before the condition as
`(void)Mod_CheckNodes(...)`. Each is refused with its reason ("does not call Mod_CheckNodes" for the
first two, "discards the result of Mod_CheckNodes" for the third), and the real tree passes.

## Stock maps

A host harness, kept outside the repository, compiles `models.c` whole (as `test_bspgraph.c` does),
reads every `maps/*.bsp` out of the paks under `<datadir>` into memory (never to disk), swaps the
header as the loaders do and runs the four checks in their order. The base game's paks must all
pass; the mission packs' and CTF's are reported.
