# FIX141: a fully transparent image in the decoder round trip

Cause: on the macOS 26 runner, `tests/check-image-decoder.sh` failed one check of 960, "encode 1x1
kind 1: not the same bytes back", the pixel `19 37 34 0`. The runner's ImageIO keeps the colour under
alpha 0 when some pixel of the image is visible, but not in an image where every pixel has alpha 0.
That is a whole-image special case of the system codec. For a non-wall texture it is not a loss any
renderer can see: an image with no visible texel draws nothing. One case sees it: `upscale_textures` gives
palette index 255 alpha 0 for every texture kind (`cl_upscale_cmd.c`, `IMGDEC_EncodePNG` writes only alpha 0 or
255), and the soft renderer converts wall textures with `transparent` false (`sw_image.c`, `R_Convert32To8bit`),
so it keeps the RGB whatever the alpha. A wall that is all index 255 would draw whatever colour the decoder left.
That needs a degenerate texture, so the effect is cosmetic.

The rule, in `tests/image/imgdecode_test.c`:

- when every pixel of the source image has alpha 0, the round trip compares alpha exactly and does not
  compare colour;
- every other image compares every byte, colour under alpha 0 included;
- a 2x1 control (`19 37 34 0` and one visible pixel) pins the colour-under-alpha-0 guarantee for
  images that have a visible pixel. It checks that the decode is 2x1 before it compares the 8 bytes (FIX143),
  so a smaller decode fails the check without being read past its allocation.

`check-image-decoder.sh` is back in `tests/ci-checks.txt`. See [FIX138](FIX138.md).
