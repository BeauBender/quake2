# FIX159: a downloaded .cfg is never run as commands

Property: a file a server makes the client download is never run, then or later, as commands.

## What the engine runs

`Cmd_Exec_f` (`exec <file>`) loads any name through the filesystem and inserts it into the command buffer, so any
file type can be run if a command names it. The names the engine runs on its own are `default.cfg`, `yq2.cfg`,
`config.cfg` and `autoexec.cfg` (`src/common/frame.c`, startup). All are `.cfg`; no other extension is parsed as
commands by the engine itself.

## Overwrite finding

`CL_DownloadFilter` refuses a name that exists in the search path (`FS_FileExists`), so most downloads cannot
overwrite an existing `config.cfg` or `autoexec.cfg`. A missing `autoexec.cfg` (the common case) could be created
by a server. The existence check does not cover every name: a name starting with `players` is written relative to
the working directory (`cl_download.c`), outside it. That is carded separately (below).

## The container route

The filesystem mounts each unnumbered `*.pak` of the write directory ahead of its loose files, at the next start
and on every `game` change (`FS_BuildGameSpecificSearchPath`). `Qcommon_ExecConfigs` runs `config.cfg` and
`autoexec.cfg` at the next start and again on every `game` change, so a downloaded `x.pak` holding `autoexec.cfg`
would be run. A stock server refuses any name with no `/` (`sv_user.c`), so no legitimate download fetches a pak,
and this fork has no HTTP download. `.pak` is the only suffix in `fs_packtypes`.

## The top-level route

The `.pak` refusal compares bytes, but the default macOS volume folds Unicode case: `pak9.pa` plus KELVIN SIGN
(U+212A, UTF-8 `E2 84 AA`) passes it, and at the next start the numbered-pak loop opens `<dir>/pak9.pak`, which the
volume resolves to that file, so its `autoexec.cfg` and `config.cfg` run. The structural fix is to refuse every name
with no `/`: `FS_AddDirToSearchPath` mounts containers only from the top of a game directory (`<dir>/pakN.pak` and
`<dir>/*.pak`), and the startup configs live there too. A stock server already refuses such names (`sv_user.c`), so
nothing legitimate is lost. The `.cfg` and `.pak` rules stay as a second layer.

Nested game roots: downloads go to `FS_Gamedir()/<name>`, and game roots are siblings of `FS_Gamedir()`, not
children; `..` is refused, so a name with a `/` cannot reach another root's top. `players*` names are written under
`BASEDIRNAME/` relative to the working directory, so `players/x` is not top-level (FIX161 moves that path).

## The change

`CL_DownloadFilter` (`src/client/cl_download.c`) refuses a name with no `/`, and a name ending in `.cfg` or `.pak`, through the same
`CL_DownloadHasExtension` rule as the library extensions: case-insensitive, after trailing numeric groups
(`x.cfg.1`), and with the usual refusal message.

## Tests

`download_filter_extension_table` in `tests/unit/test_download.c`: `autoexec.cfg`, `config.cfg`, `foo.CFG`,
`dir/x.cfg`, `default.Cfg` and `x.cfg.1` are refused; `maps/x.bsp`, `sound/x.wav`, `players/x/y.pcx`, `x.cfgs`,
`cfg/x.wav` and `x.cfg.pcx` pass.

`download_filter_extension_table` also covers `x.pak`, `pak5.pak`, `dir/X.PAK` and `x.pak.1` (refused) and `x.paks`
(accepted). `download_pak_cfg_never_runs` builds a pak holding `autoexec.cfg`, asks for it, rebuilds the search path
and shows the config does not run.

The table also has `x.bsp`, `foo.wav`, `x` and the Kelvin spelling `pak9.pa` plus U+212A with no `/` (refused), and
`download_pak_cfg_never_runs_kelvin` is the end-to-end variant: refused, and the config never runs.

The always-refused extensions are `.dll`, `.dylib`, `.lib`, `.so`, `.a`, `.cfg` and `.pak`.

## Out of scope (carded separately)

- A downloaded `.dm2` sends its stufftext when the player plays it. That is not automatic, and the attract-loop
  demos already exist in an install.
- Map entity text: a `target_changelevel` `map` key holding a newline reaches `gamemap` through `ExitLevel`.
- `players*` downloads are written relative to the working directory, outside the existence check.
