# FIX165: Cvar_WriteVariables refuses a value it cannot write back

Cause: `Cvar_WriteVariables` wrote `set <name> "<value>"` for every archived cvar. The tokenizer has no escape
(`COM_Parse` ends a quoted token at the next `"`), and `Cbuf_Execute` splits a line at a `\n` always and at a `;`
outside quotes. A value holding a `"` could therefore end its quotes early, and the `;` after it would start a
second command from `config.cfg` at the next start.

Reachability, traced in the source:

| Route | Can it produce a bad value? | Why |
|---|---|---|
| `set x "<v>" a` from server text or console | no for a quote inside quotes | `COM_Parse` ends a quoted token at the next `"`, so a quoted token holds none |
| `set x a"b;c"d a`, an unquoted word | yes | `COM_Parse` keeps a `"` inside a word. `Cbuf_Execute` counts quotes and does not split at a `;` while the count is odd, and `Cmd_MacroExpandString` and `Cvar_Set_f` accept the token. The value is `a"b;c"d` |
| `set x a"b;c a`, one lone quote | no | the buffer discards a line with an odd number of quotes ("Line has unmatched quote, discarded."); the test pins it |
| a raw `\n` from text | no | a newline always ends the line in `Cbuf_Execute`, so no token holds one |
| a `;` alone | harmless | written inside quotes, it does not split |
| userinfo and serverinfo writes | no | `Cvar_InfoValidate` refuses `\`, `"` and `;` for those flags. `set x v a` sets the flag word to `CVAR_ARCHIVE` alone, so the validation does not apply to it |
| engine code that sets archived cvars from external text (`Cvar_Set`, `Cvar_FullSet`) | possible in principle | the value is whatever the caller passes, newline and `\r` included, and nothing in `Cvar_Set2` or `Cvar_FullSet` checks it |

So one route is reachable: an unquoted word with two quotes and a `;` between them, sent as `svc_stufftext`.

The change, in `Cvar_WriteVariables` only: an archived cvar whose value (or name) holds `"`, `\n` or `\r` is
not written, and a console line names it. The tokenizer has no escape, so refusing to write is the primitive.
The cvar keeps its value for the session. A cvar that is not written keeps its default at the next start.

Test: `cvar_write_refuses_unsafe_values` (`tests/unit/test_cvar_cmd.c`). Red before the change: the
unsafe cvars were written (3 lines). Green after: none are written, the console names each, and a value with a
`;` inside quotes and a plain value are written as one `set` line each.
