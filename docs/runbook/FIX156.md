# FIX156: a server's alias or bind runs as the server's text, whoever runs it

FIX151 ([its runbook](FIX151.md)) made the commands that refuse a server's use read
`Cbuf_ExecutingServerText()`, which is true while `Cbuf_Execute` runs a line that holds a byte a
server sent (FIX113's tag, [its runbook](FIX113.md)). FIX153 ([its runbook](FIX153.md)) closed the
`nextserver` way around it. This card closes the two that remain: a server, or a demo, defines
`alias x "<gated command>"` or `bind <key> "<gated command>"`, and the body runs later from the
player's text, a key press, or the console's `d1`, as the player's. Running console commands from
a server or a demo stays by design (CLAUDE.md, "Security-relevant boundaries").

FIX148 ([its runbook](FIX148.md), section 3) left a server's aliases out of the threat model,
because each later run starts from a player action. This card takes the other view: the player
picks when the body runs, the server picked what it runs, and a gated command refuses what the
server picked.

## The property

A body that a server-tagged line wrote, as an alias or a bind, runs as server text whenever it
is expanded, so `Cbuf_ExecutingServerText()` is true while it runs. That holds until the
player's text defines that alias or binds that key again. It carries through nesting: a player
alias that names a server alias runs the server's body as server text, and an alias that a
server's body defines is the server's.

One refinement keeps a server from taking over what the player already has: a server line that
writes the body the alias or key already holds leaves its owner as it was. Without it, a server
that runs the player's own configuration again (`exec autoexec.cfg`, `exec config.cfg`) would
make every alias and bind in it the server's, and the binds would then be left out of the next
`config.cfg` (below). The body is the player's choice either way, so nothing of the server's
gets through.

## Aliases

`cmdalias_t` is private to `src/common/cmdparser.c`; it takes a `server` field. `Cmd_Alias_f`
sets it from `Cbuf_ExecutingServerText()` when it writes the body (with the refinement above).
`Cmd_ExecuteString`, the one place an alias is expanded, inserts a server alias's body with the
buffer's source set to `CBUF_SERVER` for the insert, and restores it after; a player alias's body
is inserted with the source of the line that names it, as before, so a server line that names a
player alias still queues server text. `Cbuf_InsertText` keeps the source of the text queued
behind the body, so the player's text on the same line or after it stays the player's.

Aliases are not written to `config.cfg`: `CL_WriteConfiguration` (`src/client/cl_main.c`) writes
`Key_WriteBindings` and `Cvar_WriteVariables`, and the latter writes only `set` lines for archived
cvars (`src/common/cvar.c`). There is no other writer. So an alias has no round trip to close.

## Binds

### The decision: a key bound by a server runs its binding as the server's

Pressing the key is not taken as the player's choice of the body. Three reasons:

- **The press picks when, not what.** A server can bind any key the player presses anyway (a
  movement key, the fire button), so a press is no sign that the player chose the command.
- **It matches aliases.** A bind and an alias are the same thing, a stored body run later by the
  player. A bind that names a server alias already runs it as server text through the alias
  path; tagging the bind itself makes the two agree.
- **Nothing that works today stops.** Only the commands that read `Cbuf_ExecutingServerText()`
  notice. `+attack`, `impulse`, `say`, `cmd ...` and the rest run as before. A server bind
  refused outright (the other choice) would break every server and mod that stufftexts a bind,
  which the project's no-breaking-changes rule forbids.

A private array beside `keybindings[]`, `keybindserver[]` (`src/client/cl_keyboard.c`), records
the owner; `keybindings[]` itself is unchanged, as are its readers in the menu, the inventory and
the input probe. `Key_SetBinding`, which every writer goes through (`bind`, `unbind`,
`unbindall`, the menu's unbind, iOS's default pad binds), sets it. `Key_Event` queues the
binding through `Key_AddBindingText`, which uses `Cbuf_AddServerText` for a server's binding, on
the press and on the release of a `+` command.

### The `config.cfg` round trip: a server's binding is not written

`Key_WriteBindings` writes `config.cfg`, which the next start runs as the player's text. It now
leaves out a key whose binding is the server's, so the binding lasts for the session and does
not come back as the player's. Refusing `bind` from server text would also close the round trip,
but would break servers that bind keys (above).

The cost: the key is missing from `config.cfg`. With `cfg_unbindall` set (the default),
`config.cfg` starts with `unbindall`, so after a restart the key is unbound; without it, the key
has what `default.cfg` gives it. The player's own binding that the server replaced was lost in the
stock code too, where the server's binding was saved in its place. Binding the key again from the
console or the menu makes it the player's and saves it.

### Why the bind half has no unit test

The suite links only some client files (CLAUDE.md), and `cl_keyboard.c` is not one of them:
`tests/unit/stub_client_full.c` stubs `Key_Event`, and the file needs the console, the menu and
the input layer. Linking it would mean a Makefile change outside this card's scope. The bind code
is kept to the owner flag, the one queue helper and the one write check, mirrors the alias code
that the suite tests, and is proved by `make client`.

## Every route

Line numbers are at the head of this card's code.

| Route | Where | What it does |
| --- | --- | --- |
| an alias is defined (`alias`, the only writer of the alias list) | `Cmd_Alias_f`, `src/common/cmdparser.c:640`-`653` | records whether a server line wrote it |
| an alias is expanded, from `Cbuf_Execute`, `EXEC_NOW` or a nested alias | `Cmd_ExecuteString`, `cmdparser.c:1294` | a server's body is inserted as server text |
| a key is bound or unbound | `Key_SetBinding`, `src/client/cl_keyboard.c:970`-`990` | records whether a server line wrote it |
| a key is pressed (`+` command, or a plain one) | `Key_Event`, `cl_keyboard.c:1634`, `1638`-`1639` | a server's binding is queued as server text |
| a `+` key is released | `Key_Event`, `cl_keyboard.c:1616` | the `-` command is queued as the binding's owner |
| `config.cfg` is written | `Key_WriteBindings`, `cl_keyboard.c:1169` | a server's binding is left out |

A consequence that follows from FIX113: `Cbuf_DropServerText` discards server text still queued
when the connection ends, so a server body of the form `disconnect; connect <other>` now stops
after the `disconnect` when the player runs it, as it does when a server stufftexts it.

## Proof

The tests are in `tests/unit/test_alias_source.c`. The probe is FIX151's: it stands in for
`upscale_textures` and counts the runs the real `CL_UpscaleAllowed(1, 1, 0)` lets through, with
the server state set to `ss_cinematic`, where only the line's source can refuse it. It also counts
every run, so a refusal is shown to be the gate's and not a body that never ran. Server lines go
in with `Cbuf_AddServerText`, the player's with `Cbuf_AddText`, and both run through the real
`Cbuf_Execute`.

- `alias_server_defined_runs_as_server`: a server line defines `t_as1`, the player runs it.
- `alias_player_alias_naming_server_alias`: the player's `t_as2p` names the server's `t_as2`.
- `alias_player_defined_runs_as_player`: the player's own alias with the same body runs.
- `alias_player_redefines_server_alias`: refused, the player defines it again, it runs; the
  server defines it again, refused.
- `alias_defined_by_server_body`: the server's `t_as5` defines `t_as5y` when the player runs it.
- `alias_server_same_body_stays_player`: a server line writes the player's own body again.
- `alias_server_body_leaves_player_text_after_it`: the player's text behind a server's body on
  the same line and the next stays the player's.
- `alias_server_defined_exec_now`: the alias expanded through `Cbuf_ExecuteText(EXEC_NOW)`.
