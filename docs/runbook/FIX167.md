# FIX167: the console's unbind cannot erase a saved bind the player did not see

[FIX163](FIX163.md) gave the Keys menu `Key_ClearForPlayer(k)`. The console's `unbind` had the same fault: `Key_Unbind_f` called `Key_SetBinding(b, "")`, the player's text, so on a key a server had bound it wrote `""` into the saved body (`keybindplayer[]`) that the player never saw, and `config.cfg` lost it.

## The property

`unbind` never erases a saved bind the player did not see. On a key the server owns it restores the player's saved body; on a key the player owns it clears the key as before.

## The calls

- `Key_Unbind_f` (`cl_keyboard.c`) calls `Key_ClearForPlayer(b)` after the key-name lookup, in place of `Key_SetBinding(b, "")`. A key outside the tables is still refused by the lookup's range check.
- `unbindall` is left clearing everything, saved bodies included: the player asked for every bind to go, and `config.cfg` begins with `unbindall` on purpose, so a rule that spared saved bodies would break that. A server's own `unbindall` is already harmless (FIX156).
- `doc/050_commands.md` has no `unbind` entry, so nothing is changed there.

## Tests

In `tests/unit/test_keybind.c`: `keybind_console_unbind_restores_player_body` (player saves `a = +moveleft`, a server binds `a` to `+attack`, the player runs `unbind a`: `a` is `+moveleft`, the player's, and the writer writes it) and `keybind_console_unbind_player_key` (a player key clears to `""`). `T_Kb_Unbind_f` is a stand-in for `Key_Unbind_f` (`cl_keyboard.c` is not linked), changed the same way; `make client` builds the real call. No existing test asserted that `unbind` erases a server-owned key's saved body, so none changed (`keybind_player_unbind_clears_saved` uses player keys).
