# FIX150: gaps in the image-decoder self-test, after FIX149

## What changed

- The hanging leaks(1) stubs of cases (a) and (g) of `tests/check-image-decoder-selftest.sh` end by
  themselves after 120 one-second sleeps, and write their PID to `hang.pids`, which the self-test's
  `cleanup` reads and ends through `end_own` (so a red run leaves none running).
- `tests/check-image-decoder.sh` writes the watchdog's PID to the file named by
  `IMGDEC_SELFTEST_DOGFILE`, when that variable is set, right after `dog=$!`. Nothing else reads it.
- Case (h) is now a function, `termcase`, run twice. It asserts the check ends with 143, the
  probe's stopped target and stub leaks(1) are gone, the recorded watchdog is gone, and (first run)
  no "Terminated" job-status line reached the output. The second run puts a failing `ps` first on
  PATH and asserts the trap's reap line ("ps(1) gave no answer") reaches the check's output; the
  stopped target is not asserted gone there, since that is what the line says may be left.
- `stopped` in the check waits for the watchdog it killed (`wait "$dog" 2>/dev/null`), which removes
  the shell's "Terminated: 15" job-status line from the output.

## Red on mutants

Each mutant is applied to the check on a scratch basis and reverted:

- `kill "$dog"` and its `wait` deleted from `stopped`: "(h) ... the check's watchdog is still there"
  for both runs, 2 cases failed.
- `2>&3` dropped from the trap's `reap` call: "(h) a TERM to the check with a failing ps(1): the
  trap's reap line did not reach the output", 1 case failed.
- the `wait "$dog"` line alone deleted: the output carries
  `Terminated: 15 ( n=0; while ... ) < /dev/null > /dev/null 2>&1 3>&-` and "(h) ... a job status
  line ('Terminated') reached the output" fails (the line is absent with the wait).
- `kill -KILL "$1"` dropped from the empty-`ps` branch of `reap`: case (g) fails (status 142, the
  alarm); no stub of this run was left running afterwards (`ps -x -o pid,stat,comm` before and
  after differ only by other sessions' short-lived processes).

## Known gaps

Those of FIX149's runbook remain, now including the fork-to-assignment windows and the collected-PID
KILL with its "ps(1) gave no answer" line, which are written down there.
