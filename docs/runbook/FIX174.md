# FIX174: check-gate-parallel's tty case tells a stop from a slow run

## What happened

`c_tty` in `tests/check-gate-parallel.sh` runs the gate's scheduler on a terminal set to `stty tostop`
and fails if the run has not ended in 30 s. On any timeout it said "the run stopped on a terminal with
tostop", the real bug it was written for (#386). Under host load a slow run hit the same bound and the
same message, so a load spike read as a regression of the SIGTTOU fix.

## The fix

On status 124 the case now reads the state (`ps -o stat=`) of the run's own processes: test.sh, whose
pid it records before the exec, and everything that descends from it, before it ends any of them. A
state with a `T` is a stop and gives the old tostop line. Otherwise the line is
`tty: timed out after N s (state: <pid>=<stat> ...)`. The timeout still fails the case either way.

The bound is `TTY_BOUND` (default 30 s) and a held check is `TTY_HOLD`, both read by `c_tty` only so
the new case `ttymsg` can use a short bound.

## The case that proves it

`ttymsg` runs `c_tty` twice, capturing what it says:

- a check that holds 20 s and writes nothing to the terminal, bound 3 s: must fail with the
  `timed out after 3 s` line and no tostop line (on main this said tostop: the red proof);
- the scheduler without its SIGTTOU ignore (the `ttou-scheduler` mutant): must still fail with the
  tostop line.
