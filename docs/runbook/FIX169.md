# FIX169: svc_serverdata's game directory is validated before it is stored

Property: the client never stores a game directory the filesystem would refuse.

Cause: `CL_ParseServerData` (`src/client/cl_parse.c`) copied the server's game string into `cl.gamedir` and
`Cvar_Set("game", ...)` unchecked. `FS_BuildGameSpecificSearchPath` refused `.`, `..`, `/` and `\` later, but
only after the cvar held the value, and it let control bytes and `:` through.

The rule, `FS_GameDirValid` in `src/common/filesystem.c` (prototype in `common.h`): the empty string is valid
(it means baseq2); anything else is refused if it is `.`, contains `..`, `/`, `\`, `:`, or a byte below
space or 0x7f. `FS_BuildGameSpecificSearchPath` uses it, so its behaviour changes only for values with `:` or
control bytes.

The parser calls it before `cl.gamedir` and the cvar are written. On failure it calls
`Com_Error(ERR_DROP, "Server sent an invalid game directory")`: a server that sends one is broken or hostile.

Other writers of `game`, none a client-side network read, so left alone: `cl_network.c` `CL_Disconnect`
restores `userGivenGame` (the client's own startup value); `filesystem.c` resets it to "" after a refused
directory; the `game` cvar on a listen server is the local user's. No `svc_configstring` path writes it.

Tests, `tests/unit/test_cl_parse.c`: `"x\ny"`, `"a/b"` and `".."` drop and leave `game` and `cl.gamedir`
unchanged; `"ctf"` is accepted and sets `game`.
