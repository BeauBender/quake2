# FIX180: a main merge never leaves a duplicated docs/runbook/INDEX.md row

Property: after a merge of main, one command restores the index to one row per card, taking main's version of a row both sides carried, and no gate is spent finding the duplicate.

## Cause

`.gitattributes` gives `docs/runbook/INDEX.md` `merge=union`. When main edits a row and a branch adds a row next to it, the conflict hunk holds main's new row on one side and the old row plus the added row on the other. Union keeps both sides, so the index holds two `[ID]` rows. `tests/check-runbook-index.sh` fails with `indexed twice`. This cost FIX170 and FIX154 a gate each (the `[FIX160]` row).

## Design

Option 2 of the card. `merge=union` stays, and the check stays strict.

`scripts/dedupe-runbook-index.sh [REVISION]` reads the index at `REVISION` (default `refs/remotes/origin/main`). For each `[ID]` the working index holds more than once it writes the reference's row, exactly, at the first occurrence and drops the other rows. If the reference has no row for a duplicated `[ID]`, it names the card, exits 1 and changes nothing: that duplicate is the author's own. It writes through a temporary file in `docs/runbook/` and a rename. With no duplicate it exits 0 and changes nothing.

The loop's main-merge step runs it after the merge and before any gate, then commits the result.

## Test

`tests/check-runbook-dedupe.sh` (in `tests/ci-checks.txt`), in scratch repositories with no inherited `GIT_*`, a scratch `HOME`, `git init --template=`:

- main edits a row the branch carries, the merge keeps both (asserted), the index check fails, the dedupe leaves main's row and the branch's own row, the check passes, no stray file is left;
- a duplicate main has no row for is refused with the file unchanged, and the check still fails;
- the same with `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` naming a decoy repository: same result, decoy untouched;
- no duplicate: exit 0, unchanged.

Red with the fix removed: replacing the kept row with the current one fails the first case; a refusal that does not set its failure fails the second.
