# FIX166: a bind line in config.cfg cannot split into a second command

FIX156 ([its runbook](FIX156.md)) made `config.cfg` save only the bindings the player's own text wrote. `Key_WriteBindingLines` still wrote the body between a pair of quotes unchanged, so a body that held a quote ended its own string and a body that held a line break ended the line: the rest ran as a second command at the next start. FIX165 closed the same flaw for cvars (`Cvar_WriteSafe`).

## The property

Every line the bind writer emits, fed back through `Cbuf_Execute`, runs exactly one `bind` with the same key and body.

## The change

`Key_WriteBindingLines` skips a body that holds `"`, `\n` or `\r` and prints `Not saving bind for <key>: its body holds a quote or a line break.` A body with `;` is written: inside the writer's quotes `Cbuf_Execute` does not split on it. A body typed as `bind m say "a;b"` reaches `Key_SetBinding` as `say a;b` (`Key_Bind_f` joins the arguments with a space, the quotes are gone), so the player cannot type a body with a quote through `bind`; the case is a body set another way.

## Key names

`Key_KeynumToString` returns a printable ASCII character (33 to 126) other than `;`, `"`, `'` and `$`, a gamepad button name, or a `keynames[]` table name (`SEMICOLON`, `DOUBLEQUOTE`, `DOLLAR`, `SPACE` stand for the characters that would split a line). Those names hold none of `;`, `"` or a space. Two fallback strings, `<KEY NOT FOUND>` (keynum -1) and `<UNKNOWN KEYNUM>` (no table entry), do hold a space. The writer refuses a name that is empty or holds a space, `;`, `"`, `$`, a tab, CR or LF (it does not check every control byte), so it refuses both fallbacks and a later table entry cannot reopen the flaw.

## Tests

`keybind_written_lines_round_trip` in `tests/unit/test_keybind.c` binds hostile bodies (`a"b;t_kb_probe"c`, `x" ; t_kb_probe ; "y`, a body with `\n`, one with `\r`) and safe ones (`+forward`, `say a;b`, `t_kb_probe`), writes the lines, clears the binds, runs the lines through `Cbuf_Execute`, and checks the probe never ran, the safe binds are restored exactly, the hostile ones are absent and the console names each skipped key.
