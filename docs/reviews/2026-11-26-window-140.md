## 1. Executive summary and risk verdict

The module boundaries held: no struct that crosses the renderer, game or shared API changed. The new parsers of map and asset data are bounded. Two things drift in ways that compound:

The rest is hygiene, mostly guards that cover a fixed list where the code now has more cases.

## 2. How to read the findings

- **Severity:**
  - `Blocker`: a ship-stopper or a breach of a trust boundary.
  - `Major`: structural drift that compounds.
  - `Minor`: hygiene.
  - `Info`: a result with no action, kept for the record.
- **Verification:**
  - `LIVE`: executed or observed.
  - `READ`: the code path was traced, with `file:line` cited.
  - `NEEDS-VERIFY`: unproven; the experiment that would prove it is stated.
- **Remediation:**
  - `this-review`: fixed while reviewing.
  - `carded`: a card id.
  - `decision`: an owner call, with the question stated.

## 3. Findings by theme

### Trust and failure surfaces

- **AR-01 — Major, LIVE, carded FIX203 (#781): the acceptance-verdict check passes when the GitHub API fails.**
  - **Where:** `scripts/card-acceptance.sh`, `card()`. It runs `[ "$(gh api ...)" = false ] || return 1`, then two `gh api` reads whose exit status nobody checks. It is called from `||`, so `set -e` is off inside it.
  - **Proof:** run with a stub `gh` that fails.
    - A failed issue read printed `#5 is not a card: not checked` and exited 0.
    - A failed body read (the labels read succeeding) printed `card 5: every acceptance criterion has a verdict` and exited 0.
  - **Effect:** both workflows pass on a rate limit or a 5xx: `.github/workflows/card-acceptance.yml` and `card-acceptance-pr.yml`.
  - **Gap:** `tests/check-card-acceptance.sh` has no case where a call fails.

- **AR-06 — Minor, READ, carded TASK238 (#783): a lock-holding wait with no ceiling.**
  - **Where:** `scripts/bench/core/lock.sh`, the hold-until-told loop added by FIX184.
  - **What happens:** it waits while `bench_proc_same` returns 2 ("ps gives no answer"), with INT, TERM and HUP ignored. If ps stays silent, or a recorded pid is reused by a long-lived process, the shell holding the host lock waits forever. Every heavy command then queues behind it. The comments call this deliberate.

- **AR-07 — Minor, READ, carded TASK238 (#783) with an owner question: decision 0015 says every close is checked, but three paths are not.**
  - The acceptance job has `if: github.actor == github.repository_owner`, so a close by anyone else is skipped, and a skipped job counts as passing.
  - It shares a concurrency group with `card-close-labels.yml`, so a quick close, reopen and close can cancel it. This is GitHub's documented rule; NEEDS-VERIFY by a close, reopen and close within a minute.
  - "Acceptance verdicts" is not a required check in `.github/rulesets/main-protect.json`, so decision 0015 item 4 ("is red") does not block a merge.

- **AR-08 — Minor, READ, carded TASK238 (#783) with an owner question: a merged combination can stay unverified until the nightly run.**
  - Required checks are not strict.
  - The harness job runs only the checks whose globs match a PR's paths.
  - Pushes to main share one concurrency group with `cancel-in-progress: true`.
  - So two PRs that are each green can interact on main, and every main run but the last is cancelled. The local merge gate is the only guard in between.

- **AR-14 — Info, READ, carded TASK238 (#783): ignored scratch state in a tracked folder can turn the pins check red with `git status` clean.**
  - rt-variations writes `rtvar-*.cfg` into `scripts/pins/scenarios/` and removes them in a `finally`, so a KILL leaves one behind.
  - The leftover fails `check_content`. That fails closed, but the cause is invisible.

## 5. What is genuinely sound (and why)

- **Untrusted map and asset parsing in the RT code is bounded:**
  - the entity tokenizer counts its output length and refuses an unterminated string (`rm_rtlights.c`);
  - names are copied only when they are short enough, and counts are capped;
  - texinfo indices are checked against their count;
  - WAL sizes are capped at 8192 and the pixel count at the lump length;
  - a surface's lighting styles must lie inside the lighting lump (`rm_model.c`);
  - luxels are clamped to the face (`rm_rtdir.c`);
  - triangle, vertex and slice indices are checked on the GPU (`rm_rtdir.metal`);
  - MIP sizes are bounded in `cl_upscale.c`.
- **No second denoiser:**
  - the water blur reuses `mtl_rtd_rweight`;
  - RT-primary accumulation wraps `mtl_rtt_reject`, `mtl_rtt_blend` and `mtl_rtt_count`;
  - the four `bench_on_signal` definitions are callbacks of the one shared primitive, not copies of it.
- **The harness adds no `eval` of input and no `shell=True`.** Python waits go through `scripts/lib/bounded.py` with timeouts, and `ci-select.sh` fails closed on any unreadable or unmapped input.
- **The provenance marks are kept out of `cvar_t`,** which crosses the game API.

## 6. Prevention mechanisms

Ranked by the number of finding classes retired:

1. **Enumerate, do not list (AR-03, AR-04, AR-05):** a baseline of every write-mode `Q_fopen` site and every player-only command, with a check that fails on a site or a command missing from it.
2. **A failure matrix for every API-reading check (AR-01):** a case that makes each `gh` call fail in turn and requires a non-zero exit.
3. **A parity test for every duplicated rule (AR-02, AR-09):** compile both copies and compare the whole table, or include one shared header with static size assertions.
4. **An index check for every hand-kept list (AR-11, AR-12, AR-13):** decision files against the decisions README, `TEST_OBJS` against `doc/085_unittests.md`, and `scripts/` and `tests/` against `docs/README.md`.
5. **A ceiling on every wait (AR-06):** `BENCH_LOCK_HOLD_MAX`, with a case whose ps stub never answers.
6. **CI policy as an asserted invariant (AR-07, AR-08):** `check-card-acceptance` and `check-ci-map` assert the concurrency group, the actor condition and the cancel policy chosen.
