# Unit Tests, Pins And Coverage

Yamagi Quake II has a small unit-test suite for the engine code that
reads untrusted data and drives the console: network messages, the
tokenizer and info strings, downloads, the filesystem and `.pak` files,
the collision BSP loader, cvars and the command buffer. It needs nothing
beyond a C compiler and make: no SDL, no game data, no network, no
window, and no test framework.

## Running the suite

```sh
make test
```

This builds `build/release/test/yq2test` (or `build/debug/test/` with
`DEBUG=1`) and runs it. The test binary links the same objects as the
dedicated server `q2ded`, built with the same flags, plus the client
files `cl_download.c`, `cl_parse.c`, `cl_network.c`, `cl_entities.c`,
`cl_screen.c` and the sound frontend `sound/sound.c` (see "Client
stubs" below) and the shared renderer file
`src/client/refresh/files/surf.c`; only `main()` is replaced by the
test runner. The last line says how many tests ran and how many failed; the
exit status is 1 when a test failed and 2 when no test ran at all (a
name filter that matches nothing, or a usage error), so a run that
proved nothing never passes. `make clean` removes the build.

Options for the runner go into `TEST_ARGS`:

```sh
make test TEST_ARGS=--list            # list the tests
make test TEST_ARGS="--verbose msg_"  # run tests whose name contains msg_,
                                      # and print what the engine printed
```

`--list` only prints the test names and exits 0; it is not a test run.

The suite also runs as part of `scripts/test.sh`, the check every commit
must pass. The gate calls `make test UPDATE_PINS= TEST_ARGS=`, so
neither variable set in the environment reaches it: the gate always
runs every test and only ever compares against the pins, it never
rewrites them. `scripts/coverage.sh` does the same.

## Pins

A pin is a committed expected output: the bytes a message writer
produces, the tokens the parser returns, the messages a loader prints
when it refuses a broken map. Pins are text files under
`tests/pins/unit/`, one per name, each starting with a header that says
which test produced it. A test compares what the engine does today with
the pin and fails on any difference, printing the first line that
differs.

When a change to the engine is meant to change such an output, update
the pins and review the diff:

```sh
make test UPDATE_PINS=1
git diff tests/pins/unit/
```

Only the exact value `1` turns this on; `UPDATE_PINS=0` or any other
value compares as usual.

Commit the changed pins together with the change that caused them and
say in the commit message why the output changed. A pin diff nobody
expected is a regression.

The test data (paks, maps, messages) is generated by the tests
themselves in a temporary directory; nothing is downloaded and no file
from the retail game is used.

## Writing a test

Tests live in `tests/unit/test_*.c`. `tests/unit/test.h` is the whole
interface: `TEST(name) { ... }` defines and registers a test; `T_CHECK`,
`T_EQ_INT`, `T_EQ_STR`, `T_EQ_MEM` and `T_EQ_FLT` report a failure and
go on; `T_REQUIRE` ends the test. `T_EXPECT_DROP(statement)` expects the
statement to end in `Com_Error(ERR_DROP)`, the way the engine refuses
bad data, and `t_console()` returns what the engine printed.
`t_expect_exit()` runs a function in a child process, for code that
ends in a fatal error; it returns the child's exit status, and a child
that runs longer than `t_child_timeout` seconds (10) is killed and
reported as `T_EXIT_TIMEOUT`, so a hang cannot stall the gate. A check
that fails inside the child fails the test. `t_pin(name, text)` compares against a pin.
A new `test_*.c` file is picked up by the Makefile automatically.

A test that crashes (a segfault, an abort) or a run that is
interrupted prints the name of the running test to stderr, and the
runner removes its temporary directory on every way out it can catch.

## Client stubs

The client files in the test binary run as shipped. What they call
outside the suite (the renderer, the SDL sound mixer, input, the menu,
the console, particles and temp entities, and the rest of `cl_main.c`)
is stubbed by two files: `tests/unit/stub_client.c` defines the client
state `cl_download.c` reads, and `tests/unit/stub_client_full.c` defines
empty functions and the cvar pointers for the rest. A few stubs count
what they were asked to draw (`V_AddLight`, `Draw_CharScaled`,
`Draw_PicScaled`) so a test can see what the HUD or a light would have
done; they are in `tests/unit/stub_client.h`, with `stub_client_cvars()`,
which a test calls first to give the cvars a value. A test sets up
`cls`, `cl` and `net_message` itself and reaches static functions
through the public ones (`CL_ParseServerMessage`, `CL_ReadPackets`,
`SCR_UpdateScreen`, `SV_ExecuteUserCommand`). Run `make ASAN=1
UBSAN=1 test` after a change to this code: the bounds tests rely on the
sanitizers to report an out-of-bounds access. The test objects are built
with `-fno-sanitize-recover=undefined` in that build, so a report of
undefined behaviour ends the run with a failure; the shipped binaries
keep the default and only print it.

## Coverage

```sh
scripts/coverage.sh
```

builds an instrumented copy of the suite in an emptied `build/coverage`
(so that every run starts from the same state), runs
it and prints the percentage of source lines it executed, per
directory and in total. It uses only the tools that come with the
compiler: `llvm-cov` and `llvm-profdata` (through `xcrun` on macOS) for
clang, `gcov` for gcc. It fails when one of them is missing.

The total must not fall below the floor recorded in
`scripts/coverage-floor`. When it rises by a whole percent the script
prints the new value; raise the floor in the same change so that it only
ever goes up.
