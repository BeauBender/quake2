# Unit Tests, Pins And Coverage

Yamagi Quake II has a small unit-test suite for the engine code that
reads untrusted data and drives the console: network messages, the
tokenizer and info strings, downloads, the filesystem and `.pak` files,
the collision BSP loader, cvars and the command buffer. It needs nothing
beyond a C compiler and make: no SDL, no game data, no network, no
window, and no test framework.

## Running the suite

```sh
make test
```

This builds `build/release/test/yq2test` (or `build/debug/test/` with
`DEBUG=1`) and runs it. The test binary links the same objects as the
dedicated server `q2ded`, built with the same flags, plus
`src/client/cl_download.c`; only `main()` is replaced by the test
runner. The last line says how many tests ran and how many failed; the
exit status is non-zero on any failure. `make clean` removes the build.

Options for the runner go into `TEST_ARGS`:

```sh
make test TEST_ARGS=--list            # list the tests
make test TEST_ARGS="--verbose msg_"  # run tests whose name contains msg_,
                                      # and print what the engine printed
```

The suite also runs as part of `scripts/test.sh`, the check every commit
must pass.

## Pins

A pin is a committed expected output: the bytes a message writer
produces, the tokens the parser returns, the messages a loader prints
when it refuses a broken map. Pins are text files under
`tests/pins/unit/`, one per name, each starting with a header that says
which test produced it. A test compares what the engine does today with
the pin and fails on any difference, printing the first line that
differs.

When a change to the engine is meant to change such an output, update
the pins and review the diff:

```sh
make test UPDATE_PINS=1
git diff tests/pins/unit/
```

Commit the changed pins together with the change that caused them and
say in the commit message why the output changed. A pin diff nobody
expected is a regression.

The test data (paks, maps, messages) is generated by the tests
themselves in a temporary directory; nothing is downloaded and no file
from the retail game is used.

## Writing a test

Tests live in `tests/unit/test_*.c`. `tests/unit/test.h` is the whole
interface: `TEST(name) { ... }` defines and registers a test; `T_CHECK`,
`T_EQ_INT`, `T_EQ_STR`, `T_EQ_MEM` and `T_EQ_FLT` report a failure and
go on; `T_REQUIRE` ends the test. `T_EXPECT_DROP(statement)` expects the
statement to end in `Com_Error(ERR_DROP)`, the way the engine refuses
bad data, and `t_console()` returns what the engine printed.
`t_expect_exit()` runs a function in a child process, for code that
ends in a fatal error. `t_pin(name, text)` compares against a pin.
A new `test_*.c` file is picked up by the Makefile automatically.

## Coverage

```sh
scripts/coverage.sh
```

builds an instrumented copy of the suite under `build/coverage`, runs
it and prints the percentage of source lines it executed, per
directory and in total. It uses only the tools that come with the
compiler: `llvm-cov` and `llvm-profdata` (through `xcrun` on macOS) for
clang, `gcov` for gcc. It fails when one of them is missing.

The total must not fall below the floor recorded in
`scripts/coverage-floor`. When it rises by a whole percent the script
prints the new value; raise the floor in the same change so that it only
ever goes up.
